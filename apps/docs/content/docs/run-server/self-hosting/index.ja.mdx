Werft サーバーを自分で設置し、チームで共有する方法です。ひとりで試すだけなら [開発用サーバーの実行](/run-server/dev-server) で足ります。設置方法は2つあります。自分の方法のページが、`/readyz` が 200 を返すところまでの設置手順を案内します。Kubernetes のページは公開 chart を使って kind で実行して確認しました。単一サーバーのページは最初から最後まで実行して確認していません。

## 設置方法を選ぶ

| 方法 | 実行基盤 | ページ |
| --- | --- | --- |
| 単一サーバー | Linux サーバー1台、Docker Compose。セッションごとに worker コンテナ | [単一サーバーの設置](/run-server/self-hosting/single-server) |
| Kubernetes | 公開された Helm chart。セッションごとに worker Pod | [Kubernetes の設置](/run-server/self-hosting/kubernetes) |

すでに設置済みなら [アップグレード](/run-server/self-hosting/upgrade) を読んでください。

どちらの方法でも、サーバーは API(Web コンソールを含む)、scheduler、reconciler、egress proxy、PostgreSQL、S3 互換のオブジェクトストアで構成されます。Git サーバーはないため、セッションが使う GitHub リポジトリは設定ドキュメントかコンソールで追加します。単一サーバーの設置では HA は対象外です。

## 公開されたパッケージ

設置には自分でビルドしたものではなく、`main` にマージされるたびに公開されるパッケージを使います。

| パッケージ | アドレス | 備考 |
| --- | --- | --- |
| イメージ | `ghcr.io/jeongjaesoon/werft-control-host`、`werft-worker`、`werft-egress-proxy` | タグは `main-<12>`。`linux/amd64` と `linux/arm64` を含む index。設置では digest で固定する |
| Helm chart | `oci://ghcr.io/jeongjaesoon/werft` | バージョンは `0.1.0-main-<12>`。イメージの digest と worker runtime を含む |
| SDK | npm `@werft-ai/sdk` | [SDK のインストール](/getting-started/install) |

パッケージはログインなしで取得できます。`<12>` は commit SHA の先頭12文字です。

<Callout type="warn">
`v` タグはまだありません。`main-<12>` はリリースではなく、対応するソースの保管を一部確認できないまま公開されることがあります。最初の `v` タグができると、イメージのタグは `v<バージョン>`、chart のバージョンは `v` を除いた `<バージョン>` になります。設置ページのコマンドは同じままで、単一サーバーでは同じタグを checkout します。公開イメージを取得できない場合は、リポジトリを checkout して[3つのイメージを自分でビルド](https://github.com/JeongJaeSoon/werft/blob/main/docs/operator/test-ops.md#이미지를-직접-빌드한다)します。
</Callout>

## リリース manifest を読む

リリース(`v*` タグ)ごとに GitHub Release ができ、`release-manifest.json` が付く。3 つのイメージの digest、worker runtime、chart バージョンがこの 1 ファイルにある。リポジトリを checkout せず、`gh` と `jq` で読む。以下は最初のリリースができた後のコマンドである。

```bash
TAG=v0.1.0   # 読むリリースのタグ
gh release download "$TAG" -R JeongJaeSoon/werft -p release-manifest.json -D "$TAG"   # タグごとに 1 ディレクトリ
jq -r '.images[] | "\(.image)@\(.digest)"' "$TAG/release-manifest.json"   # デプロイに使う 3 つの digest
jq -c .workerRuntime "$TAG/release-manifest.json"                          # worker runtime
jq -r '"\(.chart.ref) \(.chart.version)"' "$TAG/release-manifest.json"     # chart の場所とバージョン
```

digest は 2 つのアーキテクチャを含む index の digest で、デプロイはこの値で固定する。一度付いた manifest は変わらない。フィールドと確認方法は[リリース manifest を読む](https://github.com/JeongJaeSoon/werft/blob/main/docs/operator/images-and-supply-chain.md#릴리스-manifest-읽기)を見る。

## サーバーに接続する

SDK と HTTP API は、サーバーのアドレスと API key で接続します。TypeScript SDK は `baseUrl`(既定値は環境変数 `WERFT_BASE_URL`)と `apiKey`(`WERFT_API_KEY`)を受け取ります。既定のサーバーはないので、アドレスは必ず渡します。詳しいオプションは[クライアントの設定とエラー](/getting-started/client#クライアントのオプション)にあります。
