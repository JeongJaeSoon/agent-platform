<Callout type="warn">
公式リリースはまだない。`v*` リリースはない。リリースができると、その GitHub Release に 3 つのイメージの digest、worker runtime、chart バージョンを含む `release-manifest.json` が付く([リリース manifest を読む](#リリース-manifest-を読む))。Helm chart は `main` へのマージごとに、その run のイメージ digest を含めて `oci://ghcr.io/jeongjaesoon/werft` に公開される([公開 chart でインストール](https://github.com/JeongJaeSoon/werft/blob/main/docs/operator/kubernetes-deployment.md#게시-chart로-설치))。アプリイメージは `main` へのマージごとに `ghcr.io/jeongjaesoon/werft-<app>:main-<12>` として公開され、使うときは digest で固定する([イメージとサプライチェーン](https://github.com/JeongJaeSoon/werft/blob/main/docs/operator/images-and-supply-chain.md#main-머지마다-게시되는-이미지))。このイメージを取得できない場合はリポジトリを checkout して[3 つのイメージを直接ビルド](https://github.com/JeongJaeSoon/werft/blob/main/docs/operator/test-ops.md#이미지를-직접-빌드한다)し、checkout の compose ファイルか chart でインストールする。公開イメージと直接ビルドは、どちらも x86_64 と arm64 に対応している。
</Callout>

Werft サーバーを自分でインストールし、チームで共有する方法である。一人で試すだけのサーバーなら[開発用サーバーの実行](/run-server/dev-server)で足りる。インストールと運用のドキュメントの本文はリポジトリの [`docs/operator/`](https://github.com/JeongJaeSoon/werft/tree/main/docs/operator) にあり、韓国語で書かれている。このページはどこから読むかを案内する。

## インストール方式を選ぶ

| 方式 | 実行基盤 | ドキュメント |
| --- | --- | --- |
| 単一サーバー | Docker Compose、セッションごとに worker コンテナ | [単一サーバーへのデプロイ](https://github.com/JeongJaeSoon/werft/blob/main/docs/operator/server-deployment.md) |
| Kubernetes | 公開された Helm chart、セッションごとに worker Pod | [Kubernetes へのインストール (Helm chart)](https://github.com/JeongJaeSoon/werft/blob/main/docs/operator/kubernetes-deployment.md) |

どちらの方式でも、サーバーは API (Web コンソールを含む)、scheduler、reconciler、egress proxy、PostgreSQL、S3 互換の object store で構成される。どちらにも Git サーバーは含まれないため、セッションが使う GitHub リポジトリはコンソールか設定ドキュメントで追加する。単一サーバーのインストールでは HA は対象外である。

## リリース manifest を読む

リリース(`v*` タグ)ごとに GitHub Release ができ、`release-manifest.json` が付く。リポジトリを checkout せず、`gh` と `jq` で読む。以下は最初のリリースができた後のコマンドである。

```bash
TAG=v0.1.0   # 読むリリースのタグ
gh release download "$TAG" -R JeongJaeSoon/werft -p release-manifest.json -D "$TAG"   # タグごとに 1 ディレクトリ
jq -r '.images[] | "\(.image)@\(.digest)"' "$TAG/release-manifest.json"   # デプロイに使う 3 つの digest
jq -c .workerRuntime "$TAG/release-manifest.json"                          # worker runtime
jq -r '"\(.chart.ref) \(.chart.version)"' "$TAG/release-manifest.json"     # chart の場所とバージョン
```

digest は 2 つのアーキテクチャを含む index の digest で、デプロイはこの値で固定する。一度付いた manifest は変わらない。フィールドと確認方法は[リリース manifest を読む](https://github.com/JeongJaeSoon/werft/blob/main/docs/operator/images-and-supply-chain.md#릴리스-manifest-읽기)を見る。

## 単一サーバーのインストール手順

[単一サーバーへのデプロイ](https://github.com/JeongJaeSoon/werft/blob/main/docs/operator/server-deployment.md)の手順を要約すると次のとおりである。コマンドと失敗からの復旧は、そのドキュメントとそこからリンクされている runbook に従う。

1. ホストを準備する。Linux、Docker Engine 28 以上、Docker Compose 2.24.6 以上、NTP の同期、再起動後の Docker の自動起動が必要である。Docker のデータルートは XFS に `prjquota` 付きで mount されていなければならない。そうでないと scheduler の quota 検査が失敗し、インストールが止まる。スクリプトはリポジトリの checkout で実行するため、ホストには `git`、`jq`、`curl`、Bun 1.3.14 も必要である。
2. ネットワーク経路を決める。API は loopback に置き、SSH tunnel で接続するのが基本である。内部 DNS で公開するときは、TLS と VPN または IP allowlist を備えた reverse proxy を使い、イベントストリーム (SSE) のために buffering を切る。PostgreSQL と Docker socket は外部に開かない。
3. このインストール専用の S3 bucket を用意する。同じホストの LocalStack は再起動でオブジェクトを失うため、実サーバーのストレージには使わない。
4. 公開された 3 つのイメージの digest で release を決める。公開イメージを使えない場合は checkout でビルドし、ホストが取得できる registry に push する。設定ドキュメントも用意し、秘密の値はリポジトリ外の env ファイルにだけ置く。
5. インストールして `/readyz` を確認し、Web コンソールの `/bootstrap` で最初の owner と workspace を作成する。
6. ユーザーごとに API キーを発行する。キーの owner がセッションの owner になる。
7. バックアップ、アップグレードとロールバック、再起動後の再開を事前に練習する。

## Kubernetes のインストール手順

公開された chart でインストールすれば、リポジトリの checkout は要らない。パッケージはログインなしで取得でき、バージョンは常に正確に指定する。`main` へのマージのバージョンは `<Chart バージョン>-main-<12>` で、`<12>` は commit SHA の先頭 12 文字である。

```bash
VERSION=0.1.0-main-<12>
helm show chart oci://ghcr.io/jeongjaesoon/werft --version "$VERSION"
helm show values oci://ghcr.io/jeongjaesoon/werft --version "$VERSION" | sed -n '/^images:/,/^$/p'
```

3 つのイメージの digest と worker runtime はパッケージに含まれている。PostgreSQL、S3 bucket、namespace、Secret、インストールごとの values ファイルを [Kubernetes へのインストール](https://github.com/JeongJaeSoon/werft/blob/main/docs/operator/kubernetes-deployment.md#게시-chart로-설치)のとおりに用意してからインストールする。公開イメージは `linux/amd64` と `linux/arm64` を含むため、ノードは自分のアーキテクチャを取得する。

```bash
helm upgrade --install werft oci://ghcr.io/jeongjaesoon/werft --version "$VERSION" \
  --namespace werft -f values-<installation>.yaml --timeout 10m
```

新しいバージョンに上げるときは[公開 chart のアップグレード](https://github.com/JeongJaeSoon/werft/blob/main/docs/operator/kubernetes-deployment.md#게시-chart를-올리기)に従う。worker イメージが変わる場合は直前のイメージも渡す必要があり、`--reuse-values` では新しい chart のイメージが適用されない。

## サーバーに接続する

SDK と HTTP API は、サーバーのアドレスと API キーでサーバーに接続する。TypeScript SDK は `baseUrl` (既定値は環境変数 `WERFT_BASE_URL`) と `apiKey` (`WERFT_API_KEY`) を受け取る。既定のサーバーはないため、サーバーのアドレスは必ず渡す。SDK は[SDK のインストール](/getting-started/install)のとおり npm からインストールする。オプションの詳細は[クライアントの設定とエラー](/getting-started/client#クライアントのオプション)にある。
