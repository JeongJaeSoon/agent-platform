Werft サーバーを自分でインストールし、チームで共有する方法である。一人で試すだけのサーバーなら[開発用サーバーの実行](/run-server/dev-server)で足りる。インストールと運用のドキュメントの本文はリポジトリの [`docs/operator/`](https://github.com/JeongJaeSoon/agent-platform/tree/main/docs/operator) にあり、韓国語で書かれている。このページはどこから読むかを案内する。

## インストール方式を選ぶ

| 方式 | 実行基盤 | ドキュメント |
| --- | --- | --- |
| 単一サーバー | Docker Compose、セッションごとに worker コンテナ | [単一サーバーへのデプロイ](https://github.com/JeongJaeSoon/agent-platform/blob/main/docs/operator/server-deployment.md) |
| Kubernetes | Helm chart、セッションごとに worker Pod | [Kubernetes へのインストール (Helm chart)](https://github.com/JeongJaeSoon/agent-platform/blob/main/docs/operator/kubernetes-deployment.md) |

どちらの方式でも、サーバーは API (Web コンソールを含む)、scheduler、reconciler、egress proxy、PostgreSQL、S3 互換の object store で構成される。単一サーバーのインストールには Git サーバー (Gitea) も含まれる。Helm chart には Git サーバーがないため、Kubernetes のインストールではセッションが使うリポジトリをカタログに自分で書く。単一サーバーのインストールでは HA は対象外である。

## 単一サーバーのインストール手順

[単一サーバーへのデプロイ](https://github.com/JeongJaeSoon/agent-platform/blob/main/docs/operator/server-deployment.md)の手順を要約すると次のとおりである。コマンドと失敗からの復旧は、そのドキュメントとそこからリンクされている runbook に従う。

1. ホストを準備する。Docker Engine 28 以上、Docker Compose 2.24.6 以上、NTP の同期、再起動後の Docker の自動起動が必要である。
2. ネットワーク経路を決める。API は loopback に置き、SSH tunnel で接続するのが基本である。内部 DNS で公開するときは、TLS と VPN または IP allowlist を備えた reverse proxy を使い、イベントストリーム (SSE) のために buffering を切る。PostgreSQL と Docker socket は外部に開かない。
3. このインストール専用の S3 bucket を用意する。同じホストの LocalStack は再起動でオブジェクトを失うため、実サーバーのストレージには使わない。
4. release (イメージの digest)、設定ファイル、カタログを決め、秘密の値はリポジトリ外の env ファイルにだけ置く。
5. インストールして `/readyz` を確認し、Web コンソールの `/bootstrap` で最初の owner と workspace を作成する。
6. ユーザーごとに API キーを発行する。キーの owner がセッションの owner になる。
7. バックアップ、アップグレードとロールバック、再起動後の再開を事前に練習する。

## サーバーに接続する

SDK と HTTP API は、サーバーのアドレスと API キーでサーバーに接続する。TypeScript SDK は `baseUrl` (既定値は環境変数 `WERFT_BASE_URL`) と `apiKey` (`WERFT_API_KEY`) を受け取る。既定のサーバーはないため、サーバーのアドレスは必ず渡す。オプションの詳細は[クライアントの設定とエラー](/getting-started/client#クライアントのオプション)にある。
