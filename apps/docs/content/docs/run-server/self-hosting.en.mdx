<Callout type="warn">
There is no official release yet. No `v*` release, packaged Helm chart, or `@werft-ai/sdk` on npm exist. Every merge to `main` publishes the app images as `ghcr.io/jeongjaesoon/werft-<app>:main-<12>`; pin them by digest when you use them ([Images and supply chain](https://github.com/JeongJaeSoon/agent-platform/blob/main/docs/operator/images-and-supply-chain.md#main-머지마다-게시되는-이미지)). If you cannot pull those images, check out the repository, [build the three images yourself](https://github.com/JeongJaeSoon/agent-platform/blob/main/docs/operator/test-ops.md#이미지를-직접-빌드한다), and install from the compose files or the chart in the checkout. Building from source works on both x86_64 and arm64, but the publishing code only produces `linux/amd64` images for now.
</Callout>

This is how you install a Werft server yourself for a team to share. For a server you only try out on your own, [Run a development server](/run-server/dev-server) is enough. The installation and operations documents live in [`docs/operator/`](https://github.com/JeongJaeSoon/agent-platform/tree/main/docs/operator) in the repository, written in Korean. This page tells you where to start reading.

## Choose an installation

| Installation | Execution | Document |
| --- | --- | --- |
| Single server | Docker Compose, one worker container per session | [Single-server deployment](https://github.com/JeongJaeSoon/agent-platform/blob/main/docs/operator/server-deployment.md) |
| Kubernetes | The repository's Helm chart, one worker Pod per session | [Kubernetes installation (Helm chart)](https://github.com/JeongJaeSoon/agent-platform/blob/main/docs/operator/kubernetes-deployment.md) |

Either way, the server consists of the API (including the web console), a scheduler, a reconciler, an egress proxy, PostgreSQL, and an S3-compatible object store. Neither includes a Git server, so you name the GitHub repositories your sessions use in the catalog. High availability is out of scope for a single-server installation.

## Single-server installation steps

In short, [Single-server deployment](https://github.com/JeongJaeSoon/agent-platform/blob/main/docs/operator/server-deployment.md) goes as follows. For the commands and failure recovery, follow that document and the runbooks it links to.

1. Prepare the host. You need Linux, Docker Engine 28 or later, Docker Compose 2.24.6 or later, NTP synchronization, and Docker starting automatically after a reboot. The Docker data root must be mounted on XFS with `prjquota`; otherwise the scheduler's quota check fails and the installation stops. The scripts run from a repository checkout, so the host also needs `git`, `jq`, `curl`, and Bun 1.3.14.
2. Decide the network path. By default the API stays on loopback and users connect through an SSH tunnel. To expose it under an internal DNS name, use a reverse proxy with TLS and a VPN or IP allowlist, and turn off buffering for the event stream (SSE). Never expose PostgreSQL or the Docker socket.
3. Prepare an S3 bucket dedicated to this installation. LocalStack on the same host loses objects on reboot, so do not use it as storage for a real server.
4. Build the three images from the checkout, push them to a registry the host can pull from, and fix the release with their digests. Fix the settings file and the catalog too, and keep secret values only in an env file outside the repository.
5. Install, check `/readyz`, then create the first owner and workspace at `/bootstrap` in the web console.
6. Issue an API key for each user. The key's owner is the owner of its sessions.
7. Rehearse backup, upgrade and rollback, and resuming after a reboot in advance.

## Connect to the server

The SDK and the HTTP API connect to a server with its address and an API key. The TypeScript SDK takes `baseUrl` (default: the `WERFT_BASE_URL` environment variable) and `apiKey` (`WERFT_API_KEY`). There is no default server, so always pass the server address. The SDK is not on npm yet, so build and install it from the repository as described in [Install the SDK](/getting-started/install). The options are in [Client settings and errors](/getting-started/client#client-options).
