<Callout type="warn">
Slack でエージェントにメンションしてセッションを開始する機能や、Slack のボタンで承認する機能はまだない。Slack アプリのインストール(OAuth)と Slack イベントの受信がまだないためである。以下は、その準備としてすでにある API である。
</Callout>

| 今あるもの | API | 誰が |
| --- | --- | --- |
| 自分の Slack アカウントを Web アカウントに連携 | `POST /v1/linked-accounts/slack/start`, `…/callback`, `GET /v1/linked-accounts`, `DELETE /v1/linked-accounts/{id}` | ログインした本人 |
| エージェントに Slack アプリ(bot)を接続 | `POST`·`GET /v1/agents/{id}/identities`, `DELETE …/identities/{identity_id}` | owner·admin·そのエージェントの管理者 |
| guest のエージェント利用を許可 | `POST /v1/workspaces/{id}/slack-guest` | owner·admin |

三つとも Web ログインの cookie でのみ呼び出せる。API キーでは 403 になる。以下の例は[作成](/agents/create#ログイン)の `WEB` ヘッダーと `WS` を使う。

## guest の利用設定

Slack guest(マルチチャンネル·シングルチャンネル guest)がエージェントを使えるかどうかを決める。デフォルトはオフである。

```bash
WS=$(curl -sS "$API/v1/auth/me" "${WEB[@]}" | jq -r .workspace.id)
curl -sS "$API/v1/workspaces/$WS/slack-guest" "${WEB[@]}" \
  -d '{"slack_guest_enabled": true}' | jq .
```

```text
{
  "slack_guest_enabled": true
}
```

オンにしても、guest は自分の Slack アカウントを連携しないと使えない。Slack Connect で参加した他社のユーザーは、この設定に関係なく使えない。

## Slack アカウントの連携

Sign in with Slack(OpenID Connect)で連携する。運用者が `SLACK_OIDC_CLIENT_ID`·`SLACK_OIDC_CLIENT_SECRET`·`SLACK_OIDC_REDIRECT_URI` を設定し、そのワークスペースに確認済みの Slack インストールがある必要がある。ローカルスタックにはどちらもないため、開始リクエストは 503 になる。

```bash
curl -sS -o /dev/null -w '%{http_code}\n' -X POST "$API/v1/linked-accounts/slack/start" "${WEB[@]}"
```

```text
503
```

設定済みのインストールでは、開始リクエストが `authorize_url` を返す。その URL の Slack の認可画面で同意すると、Web の連携画面が `code` と `state` を callback に渡し、連携が完了する。連携の状態は `active`·`stale`·`revoked` である。

連携の応答と `GET /v1/linked-accounts` の各項目には、連携時に Slack が返した名前も入る。`external_user_name` は Slack の表示名（id_token の `name`）、`external_tenant_name` は Slack ワークスペース名（`https://slack.com/team_name`）である。もう一度連携すると新しい名前に置き換わる。名前を保存する前に作った連携や、Slack が名前を返さなかった連携は `null` で、Web 画面はそのとき ID を表示する。Slack のトークンは保存しない。そのため provider トークンの有効期限である `expires_at` は、Slack 連携では常に `null` である。開始応答の `expires_at` は連携リクエストの有効期限で、別の値である。

| レスポンス | 意味 |
| --- | --- |
| 409 `SLACK_NOT_INSTALLED` | このワークスペースに確認済みの Slack インストールがない |
| 409 `LINK_TEAM_MISMATCH` | インストールされていない Slack チームのアカウントである |
| 409 `LINK_TAKEN` | その Slack アカウントは別の人に連携されている |
| 409 `LINK_EXISTS` | 同じチームに自分の連携がすでにある |

## 通知の言語

プラットフォームが Slack に書く案内文(拒否の案内、失敗・回答待ちの案内、`Webで開く` リンク、Web・API から送った指示の `(Webコンソール)` 表示)は、ユーザーが Web コンソールの **言語・テーマ** で選んだ言語(한국어・日本語・English)に従います。コンソールは選んだ言語をサーバーに保存します(`PATCH /v1/auth/me`)。保存した言語がないままコンソールが韓国語以外の言語で開いた場合(ブラウザーの言語など)は、その言語を保存してコンソールと Slack の言語をそろえます。

- 本人にだけ見える拒否の案内は、その Slack アカウントに連携したユーザーの言語で書きます。
- スレッドに投稿する案内と指示の表示は、セッションを開始したユーザーの言語で書きます。スレッドは複数の人が見るため、1つの言語にそろえます。
- 言語を保存したことがないユーザーと、連携していない Slack アカウントには韓国語で届きます。

モデルの回答とユーザーが入力した内容は翻訳しません。デプロイの歓迎メッセージは受け取る人が決まらないため、韓国語で送ります。

## Slack インストールの登録

運用者がターミナルで使う経路である。Slack ワークスペースにインストール済みの Slack アプリがあれば、そのアプリの bot token でインストールを登録する。コンソールで Slack アプリを自動で作成・インストールする流れは次のバージョンで入る。CLI が Slack の `auth.test`·`bots.info` でチーム、bot ユーザー、アプリを確認し、確認済み(`verified`)のインストールを残す。アプリには bot scope `users:read` が必要である。token は環境変数 `SLACK_BOT_TOKEN` でのみ渡す。CLI は token を引数で受け取らず、出力もしない。

```bash
read -rs SLACK_BOT_TOKEN && export SLACK_BOT_TOKEN
bun run slack-install register --workspace "$WS" --app-id A0123ABCD
unset SLACK_BOT_TOKEN
```

```text
{"outcome":"verified","registration":"registered","installation_id":"…","workspace_id":"…","app_id":"A0123ABCD","team_id":"T0123ABCD","bot_user_id":"U0123ABCD"}
```

同じコマンドをもう一度実行すると、同じインストールを確認し直す(`registration: existing`)。失敗すると stderr に 1 行を書き、次の終了コードで終わる。

| 終了コード | 意味 |
| --- | --- |
| 0 | 確認済みのインストールがある |
| 2 | 引数または環境変数が正しくない |
| 3 | Slack が token を拒否した、または Slack に届かない |
| 4 | そのアプリとチームは別のワークスペースのものである(`workspace_conflict`)。そこで解除されていても、そのワークスペースだけが再登録できる |
| 5 | 登録中にインストールが解除された(`revoked`)。もう一度実行すると再び開く |
| 6 | ワークスペースが存在しない(`workspace_not_found`) |
| 7 | token が `--app-id` とは別のアプリのものである(`app_mismatch`) |
| 1 | その他のエラー |

## エージェントの Slack アプリ

### アプリ設定の読み取り

owner・admin を含むエージェント管理者が Web セッションで呼び出す。`GET /v1/agents/{id}/slack/app` は `event_url` と `events` を返す。イベント URL はサーバーの `SLACK_EVENTS_PUBLIC_URL` に `/v1/slack/events/{agent_id}` を付けた絶対 URL で、未設定なら null になる。`events.state` は `pending`・`verified`・`failed` である。インストール finalize が manifest にこのアドレスを Request URL として入れると `pending` になり、`events.url` に送ったアドレスが残る(送る前は null)。すでに `verified` のアプリに同じアドレスをもう一度入れても `verified` のままで、アドレスが変わると再び `pending` になる。そのアプリの signing secret で署名されたリクエスト(`url_verification` またはイベント)が初めて届くと `verified` になる。`url_verification` には署名と時刻を確認したうえで challenge の値だけを返す。manifest 登録に失敗すると `failed` になり、秘密値を含まない `error` コードを返す。`checked_at` は状態が最後に変わった時刻(まだなければ null)である。

finalize 後も `pending` なら、Slack はまだこのアドレスを確認できていない。公開 DNS がまだアドレスを解決できないこともあれば、Slack が manifest で入れた URL を確認していないこともある。`POST /v1/agents/{id}/slack/app/events/recheck`(コンソールの Slack タブ **詳細** の **再確認**)は manifest を Request URL とともにもう一度送る。それでも `pending` なら、Slack アプリ設定の Event Subscriptions 画面で Request URL の Verify(または Retry)を押す。コンソールの Slack タブは、アドレスを送った後 `pending` の間、同じ案内とその画面へのリンクを表示する。ローカルスタックで `scripts/slack-funnel.sh on` でアドレスを公開した場合は、最後の行の公開 DNS チェック(dns.google・cloudflare-dns.com)の警告が消えるまで待ってから Slack アプリを作成する。

`GET /v1/agents/{id}/slack/app/manifest` は現在のエージェントとサーバー設定から生成した `manifest_yaml` を返す。秘密値は含まない。

`GET /v1/agents/{id}/slack-channels?ids=C1,C2` は最大 50 個の ID の名前を返す。各 item は `id`・`name`・`state` を持ち、Slack が存在しないかアクセスできないと答えた ID だけ名前と状態が `unknown` になる。通信失敗・上位サーバーのエラーはキャッシュせずリクエスト全体が 503 になり、失効したか無効な bot token は 409 `SLACK_NOT_INSTALLED` になる。cursor と全件走査はない。アプリ・チャンネルごとに 60 秒キャッシュし、Slack 429 は `Retry-After` 付きの 503 になる。

`GET`・`PUT /v1/agents/{id}/slack/app/settings` は `{ "mention_only": true }` を読み書きする。`true` なら @メンションされたときだけ、`false` ならメンションがなくてもチャンネルへの投稿に応答する。どちらの値でも、エージェントがすでに会話中のスレッド(セッションにつながったスレッド)の返信は、メンションなしでそのセッションに続く。接続済みのチャンネルを含め、使用中のすべてのチャンネルに適用され、DM には適用されない。初期値は `true` で、アプリ作成前にも保存できる。アプリ全体のオン・オフは提供しない。

binding の `mode` は `off`(このチャンネルでは使わない)・`on`(使用中)である。`mention_only` が `false` なら、使用中のチャンネルで人がメンションなしでチャンネルに直接書いた投稿にもセッションを開く。エージェントが参加していないスレッドの返信には応答しない。

エージェントごとに自分の Slack アプリを持つ。接続には、アプリ id、チーム id、bot token が入った認証情報への参照の名前(`credential_ref`、値ではない)を送る。

```sh
curl -sS "$API/v1/agents/$AID/identities" "${WEB[@]}" \
  -d '{"provider": "slack_bot", "app_id": "A0APP", "team_id": "T0TEAM", "credential_ref": "slack/research-bot-token"}'
```

確認済みの Slack インストールがない場合は 409 `SLACK_NOT_INSTALLED` になる。インストールは運用者が上の登録 CLI で作成する。

## チャンネル参加とデプロイの歓迎メッセージ

エージェントのチャンネル(`PUT /v1/agents/{id}/slack-bindings`)を保存すると、サーバーが bot をそのチャンネルに入れる。公開チャンネルには bot が自分で参加する。非公開チャンネルは Slack が bot の自己参加を許さないので、チャンネルで `/invite @<bot>` で招待する。招待されるとサーバーが検知して続きを進める。結果は binding の `membership.state` に出る。保存していないチャンネルに bot を招待した場合も、サーバーがそのチャンネルを使用中(`on`)で接続する。保存済みのチャンネルは設定を変えない(オフにしたチャンネルはオフのまま)。

| `membership.state` | 意味 |
| --- | --- |
| `joined` | bot がチャンネルにいる |
| `awaiting_invite` | 非公開チャンネルで、招待を待っている |
| `config_error` | Slack が token か scope を拒否した(`error` に Slack のエラーコード)。アプリを再インストールする |
| `join_failed` | アーカイブ済みのチャンネルか、ワークスペースのポリシーが拒否した(`error`) |

新しい release をデプロイすると、home チャンネルに`안녕하세요, <エージェント名>입니다. 이 채널에 배포됐어요. 멘션하면 답할게요`(既定は韓国語)が一度だけ届く。同じ定義の再提出や前の release へのロールバックでは送らない。home を別のチャンネルに移すと、新しいチャンネルに一度届く。bot が home にまだいなければ、入るまで待つ。歓迎メッセージや参加が失敗してもデプロイは失敗しない。
