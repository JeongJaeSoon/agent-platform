title: "receipt"
description: Read the record of how a command ended
---

Commands such as messages, controls (interrupt, pause, resume, close, terminate, recovery decisions, profile changes), push requests and decisions, and account and key management leave a receipt. A receipt holds who did it (`actor`), what they did (`operation`, `target_ref`), and how it ended (`status`, `result`, `error`). For an asynchronous command, the response's `receipt_status` is `accepted`, and you read the receipt again to see whether it finished. The scope is `sessions:read`.

| `status` | Meaning |
| --- | --- |
| `accepted` | Received and not finished yet |
| `succeeded` | Finished. The outcome is in `result` |
| `failed` | Rejected or failed. The reason is in `error` and `result.refusal` |
| `unknown` | The outcome cannot be known |

## Read

Call `receipts.get` (`GET /v1/receipts/{id}`) with the response's `receipt_id`. Read the receipts of the request made in [Reject](/approvals/reject).

<Tabs groupId="client" persist items={["SDK", "HTTP API"]}>
<Tab>

```ts
const pr = await werft.sessions.pushRequests.get(sessionId, second.id);
for (const id of [pr.request_receipt_id, pr.resolution_receipt_id]) {
  if (!id) continue;
  const receipt = await werft.receipts.get(id);
  const result = receipt.result as { action?: string | null } | null;
  console.log(receipt.operation, receipt.status, result?.action);
}
```

```text
request_push succeeded null
resolve_push succeeded reject
```

</Tab>
<Tab>

```bash
pr=$(curl -sS "$API/v1/sessions/$SID/push-requests/$PUSH_ID" -H "Authorization: Bearer $KEY")
for id in $(echo "$pr" | jq -r '.request_receipt_id, .resolution_receipt_id'); do
  curl -sS "$API/v1/receipts/$id" -H "Authorization: Bearer $KEY" \
    | jq -c '{operation, status, actor: .actor.principal.kind, action: .result.action}'
done
```

```text
{"operation":"request_push","status":"succeeded","actor":"api_key","action":null}
{"operation":"resolve_push","status":"succeeded","actor":"api_key","action":"reject"}
```

Reference: [`GET /v1/receipts/{id}`](/reference/http-api/limits-and-receipts/getReceipt)

</Tab>
</Tabs>

For a refused request, `error.details.receipt_id` in the error body points to that receipt. This means a refusal is recorded too.

Approval and rejection receipts written by a server from before the rename have the operation `decide_push` and the value in `result.decision`. A repeated attempt's refusal is `already_decided`. Past receipts read as they were written.

## Wait until it finishes

The receipt of an asynchronous control changes from `accepted` to `succeeded` or `failed`. Check for both so the loop stops even if another outcome arrives while waiting. The SDK's `waitForReceipt` waits until the value is no longer `accepted`.

<Tabs groupId="client" persist items={["SDK", "HTTP API"]}>
<Tab>

```ts
import { waitForReceipt } from "@werft-ai/sdk";

const { revision } = await werft.sessions.get(sessionId);
const paused = await werft.sessions.pause(sessionId, {
  expected_revision: revision,
  reason: "lunch",
});
const receipt = await waitForReceipt(werft, paused.receipt_id);
const state = receipt.result as { resulting_admission_state?: string } | null;
console.log(receipt.operation, receipt.status, state?.resulting_admission_state);
```

```text
pause succeeded paused
```

</Tab>
<Tab>

```bash
REV=$(curl -sS "$API/v1/sessions/$SID" -H "Authorization: Bearer $KEY" | jq .revision)
RID=$(curl -sS "$API/v1/sessions/$SID/pause" \
  -H "Authorization: Bearer $KEY" \
  -H 'Content-Type: application/json' \
  -H "Idempotency-Key: $(uuidgen)" \
  -d "$(jq -nc --argjson r "$REV" '{expected_revision: $r, reason: "lunch"}')" | jq -r .receipt_id)
until curl -sS "$API/v1/receipts/$RID" -H "Authorization: Bearer $KEY" \
  | jq -e '.status | IN("succeeded", "failed", "unknown")' >/dev/null; do
  sleep 2
done
curl -sS "$API/v1/receipts/$RID" -H "Authorization: Bearer $KEY" \
  | jq '{operation, status, state: .result.resulting_admission_state}'
```

```text
{
  "operation": "pause",
  "status": "succeeded",
  "state": "paused"
}
```

Reference: [`POST /v1/sessions/{id}/pause`](/reference/http-api/session-control/pauseSession), [`GET /v1/receipts/{id}`](/reference/http-api/limits-and-receipts/getReceipt)

</Tab>
</Tabs>

A receipt never contains secret values. A receipt in someone else's scope is 404.
