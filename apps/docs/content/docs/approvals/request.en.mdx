title: "Request"
description: Ask to push the commit a session made to the repository's agent/<session-id> branch
---

A session does not push to the repository directly. The session's work is saved as a commit in a checkpoint, and to send that commit to the repository you create a push request. The platform (API) pushes only after a person with `sessions:approve` [approves](/approvals/approve) it. Requesting needs `sessions:write`.

| State | Meaning |
| --- | --- |
| `requested` | Waiting for a decision |
| `approved` → `pushing` | Approved, and the platform is pushing |
| `pushed` | The branch was created or updated in the repository |
| `rejected` | Rejected |
| `failed` | The push could not be done. The reason is in the [receipt](/approvals/receipt) |

## Prepare a session that changes files

The SDK examples use the `werft` client made in [Install the SDK](/getting-started/install#create-a-client), and the HTTP API examples use the shell variables `API` (the server address) and `KEY` (the key). This script appends a line to the repository's `README.md`, and the turn ends once you allow the permission request.

<Tabs groupId="client" persist items={["SDK", "HTTP API"]}>
<Tab>

```ts
import { waitForTurn } from "@werft-ai/sdk";

const note = await werft.sessions.create({
  profile_id: "claude-coding-local",
  repository_id: "sample-app",
  message:
    'GATE-SPEC {"id":"note","steps":[{"tool":"Bash","input":{"command":"echo tested >> README.md","description":"append to README.md"}}],"final":"updated README.md"}',
});
const sessionId = note.session_id;
await waitForTurn(werft, sessionId, note.turn_id, {
  onRequest: { permission: () => ({ decision: "allow" }) },
});
```

</Tab>
<Tab>

```bash
SID=$(curl -sS "$API/v1/sessions" \
  -H "Authorization: Bearer $KEY" \
  -H 'Content-Type: application/json' \
  -H "Idempotency-Key: $(uuidgen)" \
  -d "$(jq -nc --arg m 'GATE-SPEC {"id":"note","steps":[{"tool":"Bash","input":{"command":"echo tested >> README.md","description":"append to README.md"}}],"final":"updated README.md"}' \
    '{profile_id: "claude-coding-local", repository_id: "sample-app", message: $m}')" \
  | jq -r .session_id)
until [ "$(curl -sS "$API/v1/sessions/$SID" -H "Authorization: Bearer $KEY" | jq -r .status)" = needs_input ]; do
  sleep 2
done
REQ=$(curl -sS "$API/v1/sessions/$SID/pending-requests" -H "Authorization: Bearer $KEY" | jq -r '.items[0].request_id')
curl -sS "$API/v1/sessions/$SID/answers" \
  -H "Authorization: Bearer $KEY" \
  -H 'Content-Type: application/json' \
  -H "Idempotency-Key: $(uuidgen)" \
  -d "$(jq -nc --arg r "$REQ" '{request_id: $r, kind: "permission", decision: "allow"}')" > /dev/null
until [ "$(curl -sS "$API/v1/sessions/$SID/turns/1" -H "Authorization: Bearer $KEY" | jq -r .status)" = completed ]; do
  sleep 2
done
```

Reference: [`POST /v1/sessions`](/reference/http-api/sessions/createSession), [`POST /v1/sessions/{id}/answers`](/reference/http-api/pending-requests/answerPendingRequest)

## Request

The SDK passes only the session id, and the HTTP API sends an empty JSON object (`{}`) as the request body. The requester does not choose what is sent or where. The platform pins the session's latest checkpoint and its commit at that moment, the session's repository, and the branch `agent/<session-id>`.

<Tabs groupId="client" persist items={["SDK", "HTTP API"]}>
<Tab>

```ts
const push = await werft.sessions.pushRequests.create(sessionId);
console.log({
  state: push.state,
  repository_id: push.repository_id,
  checkpoint_revision: push.checkpoint_revision,
  target_branch: push.target_branch,
});
```

```text
{
  state: 'requested',
  repository_id: 'sample-app',
  checkpoint_revision: 0,
  target_branch: 'agent/…'
}
```

</Tab>
<Tab>

```bash
push=$(curl -sS "$API/v1/sessions/$SID/push-requests" \
  -H "Authorization: Bearer $KEY" \
  -H 'Content-Type: application/json' \
  -H "Idempotency-Key: $(uuidgen)" \
  -d '{}')
echo "$push" | jq '{state, repository_id, checkpoint_revision, git_commit, target_branch}'
PUSH_ID=$(echo "$push" | jq -r .id)
PUSH_COMMIT=$(echo "$push" | jq -r .git_commit)
```

```text
{
  "state": "requested",
  "repository_id": "sample-app",
  "checkpoint_revision": 0,
  "git_commit": "…",
  "target_branch": "agent/…"
}
```

Reference: [`POST /v1/sessions/{id}/push-requests`](/reference/http-api/push-requests/createPushRequest)

</Tab>
</Tabs>

The response is 201. Use `pushRequests.list` (`GET /v1/sessions/{id}/push-requests`) for the session's list of requests and `pushRequests.get` (`GET …/push-requests/{push_request_id}`) for one request.

| Response | Meaning |
| --- | --- |
| 409 `PUSH_SOURCE_MISSING` | The session has no repository or checkpoint yet |
| 409 `PUSH_REQUEST_OPEN` | An open request (`requested`, `approved`, `pushing`) already exists. One per session |
