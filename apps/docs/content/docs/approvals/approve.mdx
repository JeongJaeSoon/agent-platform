---
title: "승인"
description: push 요청이 고정한 commit을 확인하고 승인한다. 플랫폼이 몇 초 안에 push한다
---

승인에는 `sessions:approve`가 필요하다. 이 scope는 사람만 갖게 발급한다. CI 같은 자동화에는 주지 않는다. 세션을 돌리는 worker의 자격으로는 `/v1`을 부를 수 없으므로(401) 에이전트가 스스로 승인하지 못한다. [요청](/approvals/request)의 `SID`, `PUSH_ID`, `PUSH_COMMIT`을 쓴다.

## 승인하기

결정 본문의 `git_commit`은 요청이 고정한 commit과 같아야 한다. 승인하는 사람이 무엇을 승인하는지 확인했다는 표시다.

```bash
curl -sS "$API/v1/sessions/$SID/push-requests/$PUSH_ID/decision" \
  -H "Authorization: Bearer $KEY" \
  -H 'Content-Type: application/json' \
  -H "Idempotency-Key: $(uuidgen)" \
  -d "$(jq -nc --arg c "$PUSH_COMMIT" '{decision: "approve", git_commit: $c}')" \
  | jq '{state, decided_by: .decided_by.principal.kind}'
```

```text
{
  "state": "approved",
  "decided_by": "api_key"
}
```

## push 결과 보기

플랫폼은 3초마다 승인된 요청을 하나씩 집어 push한다. 요청이 `pushing`을 거쳐 `pushed`나 `failed`가 될 때까지 기다린다.

```bash
until curl -sS "$API/v1/sessions/$SID/push-requests/$PUSH_ID" -H "Authorization: Bearer $KEY" \
  | jq -e '.state | IN("pushed", "failed")' >/dev/null; do
  sleep 2
done
pushed=$(curl -sS "$API/v1/sessions/$SID/push-requests/$PUSH_ID" -H "Authorization: Bearer $KEY")
echo "$pushed" | jq '{state}'
curl -sS "$API/v1/receipts/$(echo "$pushed" | jq -r .push_receipt_id)" -H "Authorization: Bearer $KEY" \
  | jq '{operation, status, refusal: .result.refusal}'
```

```text
{
  "state": "failed"
}
{
  "operation": "push",
  "status": "failed",
  "refusal": "no_push_credential"
}
```

로컬 스택의 `sample-app` 저장소에는 push 자격 증명이 없어서 `no_push_credential`로 끝난다. 운영자가 저장소에 GitHub App이나 PAT를 설정하면([GitHub](/integrations/github)) `pushed`가 되고, receipt의 `result`에 `remote_ref`(`refs/heads/agent/<session-id>`)와 `previous_commit`이 남는다.

플랫폼은 그 commit 하나만 그 브랜치에 보낸다. force push는 하지 않는다. 기본 브랜치에는 보내지 않는다.

| `refusal` | 뜻 |
| --- | --- |
| `no_push_credential` | 저장소에 push 자격 증명이 없다 |
| `catalog_changed` | 요청 뒤에 운영자가 저장소 설정을 바꿨다. 새로 요청한다 |
| `non_fast_forward` | 원격 브랜치가 이 commit의 조상이 아니다 |
| `default_branch`, `target_refused` | 기본 브랜치이거나 `agent/<session-id>`가 아닌 브랜치다 |
| `push_failed` | 토큰 발급 실패, 원격 거절, 네트워크 오류 |

## 승인이 거절될 때

| 응답 | 뜻 |
| --- | --- |
| 409 `CHECKPOINT_MOVED` | `git_commit`이 고정된 commit과 다르거나, 요청 뒤에 세션이 checkpoint를 다시 남겼다. 이 요청은 [거부](/approvals/reject)하고 새로 요청한다 |
| 409 `PUSH_REQUEST_DECIDED` | 이미 결정한 요청이다 |
| 403 `FORBIDDEN` | key에 `sessions:approve`가 없다 |

거절된 시도에도 receipt가 남는다. 오류 본문의 `error.details.receipt_id`로 읽는다.
