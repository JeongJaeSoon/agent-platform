---
title: "ストリーミングの受信"
description: SSE でセッションのイベントを受信し、切断されたら Last-Event-ID で続きを受信する
---

`GET /v1/sessions/{id}/events` は、セッションのイベントを Server-Sent Events で送る。すでに保存されているイベントを最初から再送し、その後は新しいイベントが生まれるたびに続けて送る。scope は `sessions:read` である。[送信](/messages/send)の `SID` を使う。

## 受信する

ストリームは 15 秒ごとに keepalive を送るので、正常なときでも閉じない。下の例は `--max-time` で切断する。`curl: (28) Operation timed out` はそのために出る。

```bash
curl -sSN --max-time 5 "$API/v1/sessions/$SID/events" -H "Authorization: Bearer $KEY" \
  -o events.txt || true
grep '^event:' events.txt | sort | uniq -c
```

```text
curl: (28) Operation timed out after 5005 milliseconds with 8000 bytes received
   2 event: assistant
   2 event: result
   4 event: status
   8 event: system
   1 event: tool_result
   1 event: tool_use
```

このセッションの 2 つのターン(準備メッセージと `ls`)のイベントがすべて届いた。frame 1 つは、`event:`、`data:`、`id:` の 3 行と空行である。

```text
event: tool_use
data: {"schema_version":1,"session_id":"…","turn_id":"2","attempt_id":"att_…","occurred_at":"…","data":{…}}
id: ev_3m
```

`data` は JSON である。イベントが属するセッション・ターン・attempt と時刻を示し、イベントの内容は内側の `data` に入る。

| event | 内側の `data` |
| --- | --- |
| `system` | エンジンが知らせる開始・設定情報 |
| `assistant` | モデルのメッセージ。テキストは `message.content[]` の `type: "text"` ブロック |
| `tool_use` | モデルが呼び出したツールと入力 |
| `tool_result` | ツールの結果。失敗なら `is_error: true` |
| `question` | 権限リクエストまたは質問が発生した。応答の方法は[承認待ちと再開](/sessions/waiting-and-resume) |
| `result` | エンジンがターンを終えた。完了の判定ではない |
| `status` | セッションの状態が変わった(`phase`: `running`、`idle` など) |
| `error` | 実行エラー |

## テキストとツール結果を取り出す

```bash
awk '/^event: assistant/ { getline; sub(/^data: /, ""); print }' events.txt \
  | jq -r '.data.message.content[] | select(.type == "text") | .text'
awk '/^event: tool_result/ { getline; sub(/^data: /, ""); print }' events.txt \
  | jq -c '.data | {is_error}'
```

```text
ready
listed
{"is_error":false}
```

ターンが終わったかどうかは、イベントではなくターンの `status` で確認する([送信](/messages/send#結果を読む))。作業ができたかどうかは、`assistant` と `tool_result` の内容で判断する。

## 切断後に続きを受信する

最後に受信した `id` を `Last-Event-ID` ヘッダーで送ると、その次のイベントから受信できる。受信済みのイベントは再送されない。

```bash
LAST=$(awk '/^id: / { id = $2 } END { sub(/\r$/, "", id); print id }' events.txt)
curl -sSN --max-time 3 "$API/v1/sessions/$SID/events" \
  -H "Authorization: Bearer $KEY" -H "Last-Event-ID: $LAST" > more.txt || true
grep -c '^event:' more.txt || true
```

```text
curl: (28) Operation timed out after 3005 milliseconds with 0 bytes received
0
```

その後は新しいイベントがなく、何も届かなかった。その間に次のメッセージを送っていれば、そのターンのイベントが届く。

| レスポンス | 意味 |
| --- | --- |
| 410 `CURSOR_EXPIRED` | その `id` が保持範囲の外にある。セッションとターンを HTTP で読み直し、新しく接続する。現在のサーバーはイベントを削除しないためこのレスポンスは返さないが、クライアントでは処理しておく |
| 429 | 同時に開いているストリームが多すぎる |
