Werft는 `@werft-ai/sdk`(TypeScript SDK)로 쓴다. SDK는 이미 떠 있는 Werft 서버에 API key로 붙는다. 이 쪽은 SDK를 설치하고, 서버 주소와 key를 넘겨 클라이언트를 만들고, 연결을 확인한다.

## 준비물

| 항목 | 내용 |
| --- | --- |
| Werft 서버 주소 | 예: `https://werft.example.com`. 로컬에서 띄웠다면 `http://127.0.0.1:3000` |
| API key | `csp_`로 시작하는 Bearer 토큰. 세션을 만들려면 `sessions:read`, `sessions:write`가, 권한 요청에 답하고 세션을 닫으려면 `sessions:approve`, `sessions:control`도 필요하다 |
| Node 20.3 이상 또는 Bun | SDK가 도는 런타임 |

<Callout type="info">
서버가 아직 없으면 [서버 실행하기](/server/dev)대로 한 머신에 개발용 서버를 띄운다. 그 쪽에 key를 발급하는 명령도 있다. 운영하는 서버라면 웹 콘솔에서 key를 발급한다([API key](/api-keys)).
</Callout>

## 설치

```sh
npm install @werft-ai/sdk
```

<Callout type="warn">
`@werft-ai/sdk`는 아직 npm 레지스트리에 올라가지 않았다. 그때까지는 저장소에서 패키지를 빌드해 tarball로 설치한다. 저장소가 고정한 Bun 1.3.14와 npm이 필요하다.

```sh
git clone https://github.com/JeongJaeSoon/agent-platform.git
cd agent-platform
bun install
bun run --cwd packages/sdk build:package
npm pack ./packages/sdk/dist
```

`werft-ai-sdk-0.1.0.tgz`가 생긴다. 앱 디렉터리에서 `npm install <저장소 경로>/werft-ai-sdk-0.1.0.tgz`로 설치한다.
</Callout>

SDK 패키지는 Apache License 2.0이다. 서버와 저장소의 나머지는 PolyForm Small Business License 1.0.0을 따르는 source-available 코드다.

## 클라이언트 만들기

`Werft`를 만들 때 서버 주소(`baseUrl`)와 API key(`apiKey`)를 넘긴다. 서버 주소에는 기본값이 없다. key는 코드에 적지 말고 환경 변수에서 읽는다.

```ts title="werft.ts"
import { Werft } from "@werft-ai/sdk";

export const werft = new Werft({
  baseUrl: "http://127.0.0.1:3000",
  apiKey: process.env.WERFT_API_KEY,
});
```

- `baseUrl`은 서버의 주소다. `/v1`은 붙이지 않는다.
- 옵션을 빼면 `WERFT_BASE_URL`, `WERFT_API_KEY` 환경 변수를 읽는다. 둘 다 없으면 `new Werft()`가 `TypeError`를 던진다.
- loopback이 아닌 주소에 `http://`를 쓰면 key가 평문으로 지나가므로 거절한다. 원격 서버는 `https://`로 붙는다.
- 브라우저에서는 만들 수 없다. 페이지에 key를 두면 새기 때문이다. 옵션 전체는 [TypeScript SDK](/sdk#클라이언트-옵션)에 있다.

## 연결 확인

key의 주인과 scope, 서버가 가진 실행 프로필을 읽는다.

<Tabs groupId="client" persist items={["SDK", "HTTP API"]}>
<Tab>

```ts title="check.ts"
import { werft } from "./werft.ts";

const me = await werft.auth.me();
console.log(me.principal.kind, me.scopes);

const { items } = await werft.profiles.list();
for (const profile of items) console.log(profile.id, profile.repository_mode);
```

```bash
WERFT_API_KEY=… node check.ts
```

```text
api_key [
  'sessions:read',
  'sessions:write',
  'sessions:approve',
  'sessions:control',
  'sessions:recover'
]
claude-coding-auto required
claude-coding-local required
general none
```

Node 22.18 이상과 Bun은 `.ts` 파일을 바로 돌린다. 그보다 낮은 Node에서는 `npx tsx check.ts`로 돌린다. key가 틀리면 `APIError`(401)가, 주소가 틀리면 `ConnectionError`가 난다.

</Tab>
<Tab>

SDK 없이 curl로 부를 때는 모든 요청에 `Authorization: Bearer <key>`를 붙인다. 이 문서의 HTTP API 예제는 서버 주소를 `API`, key를 `KEY` 변수에 둔다.

```bash
API=http://127.0.0.1:3000
curl -sS -w '\n' "$API/v1" -H "Authorization: Bearer $KEY"
curl -sS "$API/v1/profiles" -H "Authorization: Bearer $KEY" | jq -c '.items[] | {id, repository_mode}'
```

```text
{"status":"ok","owner_id":"quickstart"}
{"id":"claude-coding-auto","repository_mode":"required"}
{"id":"claude-coding-local","repository_mode":"required"}
{"id":"general","repository_mode":"none"}
```

레퍼런스: [`GET /v1`](/reference/http-api/auth/getApiRoot), [`GET /v1/profiles`](/reference/http-api/agents/listProfiles)

</Tab>
</Tabs>
