서버가 이미 있다고 전제한다. 서버가 없으면 [서버 실행하기](/run-server/dev-server)에서 띄우고 API key를 받는다. 세션 하나를 만들어 첫 turn이 끝나는 것까지 본다. 아래 예제의 저장소, 프로필, `GATE-SPEC` 대본은 `--fake-model`로 띄운 개발용 서버 기준이다. 같은 터미널에서 순서대로 실행한다.

## 서버에 붙기

[준비](/getting-started/install)의 `API`(서버 주소)와 `KEY`(API key)를 쓴다. key가 맞는지 본다.

```bash
curl -sS -w '\n' "$API/v1" -H "Authorization: Bearer $KEY"
```

```text
{"status":"ok","owner_id":"quickstart"}
```

## 실행 프로필 고르기

세션은 운영자가 등록한 실행 프로필(profile) 중 하나로 돈다. 로컬 fake 스택에는 저장소를 쓰는 `claude-coding-local`(권한 요청에 사람이 답한다)과 `claude-coding-auto`(분류기가 판정한다), 저장소 없이 도는 `general`이 있다.

```bash
curl -sS "$API/v1/profiles" -H "Authorization: Bearer $KEY" | jq '.items[] | {id, model, repository_mode}'
```

```text
{
  "id": "claude-coding-local",
  "model": "claude-sonnet-5",
  "repository_mode": "required"
}
```

## 세션 만들기

```bash
created=$(curl -sS "$API/v1/sessions" \
  -H "Authorization: Bearer $KEY" \
  -H 'Content-Type: application/json' \
  -H "Idempotency-Key: $(uuidgen)" \
  -d '{
    "profile_id": "claude-coding-local",
    "repository_id": "sample-app",
    "message": "GATE-SPEC {\"id\":\"hello\",\"steps\":[],\"final\":\"hello from Werft\"}"
  }')
echo "$created" | jq .
SID=$(echo "$created" | jq -r .session_id)
```

```text
{
  "session_id": "…",
  "turn_id": "1",
  "receipt_id": "…",
  "receipt_status": "accepted",
  "status": "queued"
}
```

- `repository_id`는 세션이 clone할 저장소다. 로컬 스택의 Gitea에 `sample-app`이 들어 있다.
- `message`는 첫 turn의 입력이다. fake 모델은 `GATE-SPEC {…}` 대본을 읽고 그대로 답한다. 이 대본은 도구를 부르지 않고 `hello from Werft`로 끝난다. 실제 Claude 스택에서는 평범한 문장을 쓴다.
- 세션 API의 POST에는 `Idempotency-Key`가 필요하다. 같은 key로 다시 보내면 처음 응답이 그대로 온다.

## turn 끝나기 기다리기

scheduler가 worker를 띄우고 worker가 저장소를 clone한 뒤 turn 1을 돈다. 처음에는 수십 초 걸린다.

```bash
until [ "$(curl -sS "$API/v1/sessions/$SID/turns/1" -H "Authorization: Bearer $KEY" | jq -r .status)" = completed ]; do
  sleep 2
done
curl -sS "$API/v1/sessions/$SID/turns/1" -H "Authorization: Bearer $KEY" | jq '{turn_id, status}'
```

```text
{
  "turn_id": "1",
  "status": "completed"
}
```

turn이 끝났는지는 turn 조회의 `status`로만 판단한다. `completed`·`failed`·`interrupted`·`cancelled`·`outcome_unknown`이 끝난 상태다.

## 모델의 답 보기

세션에서 일어난 일은 이벤트 스트림(SSE)으로 온다. 스트림은 서버가 닫지 않으므로 여기서는 5초 뒤 끊는다.

```bash
curl -sSN --max-time 5 "$API/v1/sessions/$SID/events" -H "Authorization: Bearer $KEY" \
  | awk '/^event: assistant/ { getline; sub(/^data: /, ""); print }' \
  | jq -r '.data.text // empty' || true
```

```text
curl: (28) Operation timed out after 5002 milliseconds with 3362 bytes received
hello from Werft
```

이벤트 하나는 `event:` 줄(종류)과 `data:` 줄(JSON)이다. assistant 이벤트의 `data.text`가 모델이 보낸 텍스트다. `curl: (28) Operation timed out`은 `--max-time`이 끊은 것이라 정상이다.
