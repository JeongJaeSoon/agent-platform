| | 단일 서버 | Kubernetes |
| --- | --- | --- |
| 설치 | Docker Compose, `local-docker` 실행 기반 | Helm chart, Kubernetes 실행 backend |

| 문서 | [단일 서버 배포](https://github.com/JeongJaeSoon/agent-platform/blob/main/docs/operator/server-deployment.md) | [Kubernetes 설치 (Helm chart)](https://github.com/JeongJaeSoon/agent-platform/blob/main/docs/operator/kubernetes-deployment.md) |

## 단일 서버의 순서

1. **호스트 준비.** Linux, Docker Engine 28 이상, Docker Compose 2.24.6 이상. Docker data root는 XFS `prjquota`로 mount하고, NTP를 맞추고, Docker가 재부팅 뒤 스스로 뜨게 둔다. API·Gitea·PostgreSQL 포트와 Docker socket은 인터넷에 열지 않는다.
2. **네트워크 경로.** 기본은 API를 `127.0.0.1`에만 두고 사용자가 SSH tunnel로 붙는 것이다. 내부 DNS 이름으로 내보낼 때는 TLS와 VPN 또는 IP allowlist를 갖춘 reverse proxy를 앞에 둔다. 이벤트 스트림이 오래 열려 있으므로 proxy의 buffering을 끄고 read timeout을 길게 둔다.
3. **object store.** checkpoint를 담을 전용 S3 bucket을 준비한다. 같은 호스트의 로컬 S3는 실서버의 보존 근거로 쓰지 않는다.
4. **설정과 설치.** release와 설정을 고정하고 설치한 뒤, 첫 세션이 도는지 확인한다.
5. **운영.** 백업과 복원, 업그레이드와 롤백, 재부팅 뒤 복구를 미리 연습한다.

## SDK가 붙을 주소

SDK 클라이언트의 `baseUrl`은 사용자가 API에 닿는 주소다.

| 경로 | `baseUrl` |
| --- | --- |
| SSH tunnel로 loopback에 붙는다 | `http://127.0.0.1:<tunnel 포트>` |
| TLS reverse proxy 뒤 | `https://<내부 DNS 이름>` |

SDK는 loopback이 아닌 주소로 가는 `http://`를 거절한다. key가 평문으로 지나가기 때문이다. 원격 서버는 TLS로 내보낸다.

사용자 key는 웹 콘솔에서 각자 발급한다([API key](/api-keys)). key의 owner가 그 key로 만든 세션의 owner가 된다.
