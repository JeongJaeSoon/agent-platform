세션 상세(`GET /v1/sessions/{id}`)에는 상태가 둘 있다. `status`는 지금 실행이 어떤지, `admission_state`는 세션이 새 입력을 받는지다. turn은 따로 상태를 갖고, 끝났는지는 turn 상태로만 판단한다. [시작](/sessions/start)에서 만든 `SID`로 본다.

```bash
until [ "$(curl -sS "$API/v1/sessions/$SID/turns/1" -H "Authorization: Bearer $KEY" | jq -r .status)" = completed ]; do
  sleep 2
done
curl -sS "$API/v1/sessions/$SID" -H "Authorization: Bearer $KEY" \
  | jq '{status, admission_state, current_turn_id, revision, attention}'
```

```text
{
  "status": "idle",
  "admission_state": "active",
  "current_turn_id": null,
  "revision": 0,
  "attention": null
}
```

`revision`은 pause·resume·close 같은 제어로 세션이 바뀔 때 오른다. turn이 끝나는 것으로는 오르지 않는다. 제어 요청에는 지금 값을 `expected_revision`으로 보낸다.

## status

| 값 | 뜻 |
| --- | --- |
| `queued` | 입력이 있고 worker를 기다린다 |
| `running` | worker가 turn을 돌고 있다 |
| `needs_input` | 돌고 있는 turn이 답할 수 있는 권한 요청이나 질문을 기다린다 |
| `idle` | 돌 turn이 없다. 다음 메시지를 받는다 |
| `stopped` | 실행이 멈췄다(interrupt, terminate, pause, close 뒤) |
| `failed` | 실행이 실패했다. `attention`에 이유가 있다 |

## admission_state

| 값 | 뜻 |
| --- | --- |
| `active` | 메시지와 제어를 받는다 |
| `pausing` → `paused` | pause 중, 그리고 checkpoint를 남기고 worker가 내려간 상태. 메시지는 409 `SESSION_PAUSED` |
| `resuming` | resume 중. 새 worker가 checkpoint에서 복원한다 |
| `stopping` → `stopped` | terminate 중, 그리고 멈춘 상태 |
| `recovery_required` | 결과를 알 수 없는 turn이 남아 사람이 복구 결정을 해야 한다([닫기](/sessions/close)) |
| `closing` → `closed` | close 중, 그리고 닫힌 상태. 되돌릴 수 없다 |

## turn 상태

```bash
curl -sS "$API/v1/sessions/$SID/turns" -H "Authorization: Bearer $KEY" | jq -c '.items[] | {turn_id, status}'
```

`queued`·`running`·`needs_input`은 진행 중이고, `completed`·`failed`·`interrupted`·`cancelled`·`outcome_unknown`은 끝난 상태다. `completed`는 엔진이 turn을 정상 종료했다는 뜻이지, 요청한 일을 다 했다는 뜻은 아니다. 일이 끝났는지는 이벤트의 `assistant`·`tool_result`를 읽고 판단한다. 이벤트의 `result`도 완료 판정이 아니다.

## interrupt

돌고 있는 turn 하나만 멈춘다. worker는 남아 다음 메시지를 받는다. 아래 대본은 답을 5분 늦게 보내서, 그동안 turn이 `running`에 머문다.

```bash
turn=$(curl -sS "$API/v1/sessions/$SID/messages" \
  -H "Authorization: Bearer $KEY" \
  -H 'Content-Type: application/json' \
  -H "Idempotency-Key: $(uuidgen)" \
  -d "$(jq -nc --arg m 'GATE-SPEC {"id":"slow","steps":[],"final":"too late","finalDelayMs":300000}' '{message: $m}')" \
  | jq -r .turn_id)
until [ "$(curl -sS "$API/v1/sessions/$SID/turns/$turn" -H "Authorization: Bearer $KEY" | jq -r .status)" = running ]; do
  sleep 1
done
curl -sS "$API/v1/sessions/$SID/interrupt" \
  -H "Authorization: Bearer $KEY" \
  -H 'Content-Type: application/json' \
  -H "Idempotency-Key: $(uuidgen)" \
  -d "$(jq -nc --arg t "$turn" '{target_turn_id: $t}')" | jq '{receipt_status}'
until [ "$(curl -sS "$API/v1/sessions/$SID/turns/$turn" -H "Authorization: Bearer $KEY" | jq -r .status)" = interrupted ]; do
  sleep 1
done
curl -sS "$API/v1/sessions/$SID" -H "Authorization: Bearer $KEY" | jq '{status, admission_state}'
```

```text
{
  "receipt_status": "accepted"
}
{
  "status": "stopped",
  "admission_state": "active"
}
```

아직 시작하지 않은 turn은 409 `TURN_NOT_STARTED`, 이미 끝난 turn은 아무것도 하지 않는 성공(`no_op: true`)이다. scope는 `sessions:control`이다.

## attention

세션이 사람의 손을 기다릴 때 `attention`에 `code`와 이유가 붙는다. 평소에는 `null`이다.

| code | 뜻 |
| --- | --- |
| `PAUSE_BLOCKED`, `CLOSE_BLOCKED` | pause·close가 60초 넘게 drain하지 못했다. 이유는 `long_turn`, `pending_request` 등 |
| `BUDGET_EXCEEDED` | 세션 비용이나 token 상한을 넘었다 |
| `TRANSCRIPT_LIMIT` | 대화 기록이 상한에 다가갔거나 넘었다. 새 세션으로 옮길 때다 |
| `STARTUP_FAILED`, `RESTORE_FAILED` | worker가 시작하거나 checkpoint를 복원하지 못한다 |
| `CATALOG_MISMATCH` | 세션을 만든 뒤 운영자가 프로필이나 저장소 설정을 바꿨다 |
| `CONTEXT_GAP` | 복구 결정으로 이전 대화의 일부가 빠졌다 |

## 사용량

```bash
curl -sS "$API/v1/sessions/$SID/usage" -H "Authorization: Bearer $KEY" \
  | jq '{cost: .cost.amount_usd, complete: .cost.complete, budget_exceeded}'
```

```text
{
  "cost": "0.000042",
  "complete": true,
  "budget_exceeded": false
}
```

비용은 청구액이 아니라 가격표로 계산한 추정치다. `complete`가 `false`면 합계가 아직 정해지지 않았다. 열린 turn이 있거나(`open_turn_count`), 끝난 turn 가운데 비용이 보고되지 않은 것이 있다(`unreported_turn_count`). 뒤의 경우는 모든 turn이 끝나도 `false`로 남는다.

기간 동안 내가 시작한 세션을 모두 더하려면 `GET /v1/usage/summary`를 쓴다. `since`는 날짜(그 날 00:00 UTC)나 offset이 붙은 시각이고, `until`을 빼면 지금까지다.

```bash
curl -sS "$API/v1/usage/summary?scope=me&since=2026-10-01" -H "Authorization: Bearer $KEY" \
  | jq '{session_count, cost_usd, cost_complete, token_count, run_seconds}'
```

기간 안에 만든 세션이 대상이고, `cost_usd`는 그 세션들 `/usage`의 `cost.amount_usd` 합이다. 그 가운데 하나라도 `complete: false`면 `cost_complete`도 `false`다. 개인 key는 만든 사람의 세션을 더한다. `scope=installation`(모든 owner의 세션)과 `GET /v1/limits`는 로그인한 workspace owner만 읽고, 다른 구성원과 모든 API key는 403이다.
