---

에이전트는 워크스페이스 안의 이름 붙은 정의다. 정의는 카드(역할, 지시문, 모델, 도구)이고, 카드를 고칠 때마다 새 version이 쌓인다. version 하나를 실행 프로필과 묶은 것이 release이고, 에이전트가 가리키는 release가 활성 release다. 세션을 만들 때 release를 넣으면 그 세션은 그 에이전트의 것이 된다.

<Callout type="warn">
지금 세션은 `profile_id`의 실행 프로필로 돈다. release의 지시문과 도구 목록은 세션에 기록만 되고 모델에는 아직 전달되지 않는다. 자세한 내용은 [지시문과 역할](/agents/instructions-and-roles)과 [권한](/agents/permissions)에 있다.
</Callout>

## 웹 콘솔에서

로컬 스택의 웹 콘솔은 `http://127.0.0.1:3000/`이다.

1. 처음 한 번은 `/bootstrap`에서 첫 owner와 워크스페이스를 만든다. bootstrap token은 API가 처음 뜰 때 로그에 한 번 찍는다: `docker compose logs api | grep BOOTSTRAP_TOKEN=`
2. 로그인한 뒤 상단의 "에이전트" → "새 에이전트"로 간다.
3. 이름, 주소 이름(slug), 역할, 지시 사항, 모델, 도구를 넣고 "에이전트 만들기"를 누른다. version 1이 생긴다.
4. 상세 화면에서 version과 runtime profile을 골라 "release 만들기"를 누른다.
5. 만든 release의 "활성화"를 누른다.

owner·admin·member 모두 에이전트를 만들 수 있고, 만든 사람이 그 에이전트의 관리자가 된다.

## API로

에이전트 API는 웹 콘솔과 같은 cookie 로그인으로만 부른다. API key로 부르면 403이다.

### 로그인

```sh
read -rs AP_PASSWORD
AP_COOKIE=$(curl -sS -o /dev/null -D - "$API/v1/auth/login" \
  -H 'Content-Type: application/json' -H 'X-Requested-With: agent-platform-web' \
  -d "$(jq -nc --arg e 'owner@example.test' --arg p "$AP_PASSWORD" '{email: $e, password: $p}')" \
  | sed -n 's/^[Ss]et-[Cc]ookie: \(__Host-ap_session=[^;]*\).*/\1/p')
```

로그인 cookie는 `__Host-` 이름이고 `Secure`라서 http에서는 curl의 cookie jar가 저장하지 않는다. 그래서 응답 헤더에서 꺼내 `Cookie` 헤더로 보낸다. 상태를 바꾸는 요청에는 `X-Requested-With: agent-platform-web`이 필요하다.

```bash
WEB=(-H 'Content-Type: application/json' -H 'X-Requested-With: agent-platform-web' -H "Cookie: $AP_COOKIE")
curl -sS "$API/v1/auth/me" "${WEB[@]}" | jq '{role: .principal.role, workspace: .workspace.slug}'
```

### 만들기

```bash
agent=$(curl -sS "$API/v1/agents" "${WEB[@]}" -d '{
  "slug": "research-bot",
  "name": "Research Bot",
  "card": {
    "role": "저장소를 읽고 질문에 답한다",
    "instructions": "Answer briefly. Cite file paths.",
    "model": "claude-sonnet-5",
    "capabilities": { "tools": ["Read", "Grep", "Glob"], "mcp": null }
  }
}')
AID=$(echo "$agent" | jq -r .agent.id)
VID=$(echo "$agent" | jq -r '.versions[0].id')
echo "$agent" | jq '{slug: .agent.slug, version: .versions[0].version_no, active_release_id: .agent.active_release_id}'
```

```text
{
  "slug": "research-bot",
  "version": 1,
  "active_release_id": null
}
```

같은 워크스페이스에 같은 slug가 있으면 409 `ALREADY_EXISTS`다. 만들기만으로는 아무것도 활성화되지 않는다.

### release 만들기

release는 version 하나와 실행 프로필 하나를 묶는다. 카드의 `model`이 프로필의 모델과 다르거나, 카드의 도구가 프로필에 없으면 422다.

```bash
release=$(curl -sS "$API/v1/agents/$AID/releases" "${WEB[@]}" \
  -d "$(jq -nc --arg v "$VID" '{version_id: $v, runtime_profile_id: "claude-coding-local"}')")
REL=$(echo "$release" | jq -r .release.id)
echo "$release" | jq '{id: .release.id, created, tools: .release.effective_tools.tools}'
```

```text
{
  "id": "sha256:…",
  "created": true,
  "tools": [
    "Read",
    "Glob",
    "Grep"
  ]
}
```

release id는 카드와 프로필 내용의 해시다. 같은 내용으로 다시 만들면 같은 release가 `created: false`로 온다.

### 활성화

`expected_revision`은 에이전트의 지금 `activation_revision`이다. 처음에는 `-1`이다. 다른 곳에서 먼저 바꿨으면 409 `REVISION_CONFLICT`다.

```bash
curl -sS "$API/v1/agents/$AID/activate" "${WEB[@]}" \
  -d "$(jq -nc --arg r "$REL" '{release_id: $r, expected_revision: -1}')" \
  | jq '{activation_revision, previous_release_id}'
```

```text
{
  "activation_revision": 0,
  "previous_release_id": null
}
```

## 세션에 묶기

`POST /v1/sessions`에 `agent_release_id`를 넣는다. `profile_id`는 그 release의 프로필이어야 한다(아니면 409 `RELEASE_PROFILE_MISMATCH`). 에이전트는 워크스페이스에 있으므로 key도 그 워크스페이스의 key여야 한다. 운영자 CLI로는 `--workspace`를 주고 발급한다.

```bash
WS=$(curl -sS "$API/v1/auth/me" "${WEB[@]}" | jq -r .workspace.id)
WS_KEY=$(scripts/local.sh key --workspace "$WS" --scopes sessions:read,sessions:write)
curl -sS "$API/v1/sessions" \
  -H "Authorization: Bearer $WS_KEY" \
  -H 'Content-Type: application/json' \
  -H "Idempotency-Key: $(uuidgen)" \
  -d "$(jq -nc --arg r "$REL" --arg m 'GATE-SPEC {"id":"agent","steps":[],"final":"hello from research-bot"}' \
    '{profile_id: "claude-coding-local", repository_id: "sample-app", agent_release_id: $r, message: $m}')" \
  | jq '{status, turn_id}'
```

```text
key_id …
{
  "status": "queued",
  "turn_id": "1"
}
```

워크스페이스에 없는 key(예: `scripts/local.sh key quickstart …`)로 보내면 release를 찾지 못해 404다.
