---
title: "Choose a run profile"
description: The run profile that decides which model, tools, and permission mode a session runs with
---

A run profile (profile) decides how a session runs: the runtime and its version, the model, the tool list, the permission mode, the model provider, and whether it uses a repository. The operator registers profiles in the installation's catalog (`config/profiles.yaml`), and users choose one by id. The list of profiles that can run for each repository is also in a catalog (`config/repositories.yaml`).

## List profiles

```bash
curl -sS "$API/v1/profiles" -H "Authorization: Bearer $KEY" | jq '.items[]'
```

```text
{
  "id": "claude-coding-local",
  "model": "claude-sonnet-5",
  "tools": [
    "Read",
    "Edit",
    "Write",
    "Glob",
    "Grep",
    "Bash",
    "AskUserQuestion"
  ],
  "runtime_kind": "claude_agent_sdk",
  "runtime_version": "0.3.270",
  "billing": "metered",
  "repository_mode": "required"
}
```

| Field | Meaning |
| --- | --- |
| `model` | Default model |
| `tools` | Tools a session can use. Tools outside the list are not run ([Permissions](/agents/permissions)) |
| `billing` | With `metered`, cost counts toward the session limit. With `none`, cost is not counted |
| `repository_mode` | `required` (a repository is mandatory), `optional`, or `none` (no repository) |

The provider address and credentials do not appear in the list. Those values do not go to the worker either.

## Choose in a session

Choose with `profile_id` when you create a session. If the profile allows several models, choose one of them with `model`; if you leave it out, the session runs with the default model.

```bash
created=$(curl -sS "$API/v1/sessions" \
  -H "Authorization: Bearer $KEY" \
  -H 'Content-Type: application/json' \
  -H "Idempotency-Key: $(uuidgen)" \
  -d "$(jq -nc --arg m 'GATE-SPEC {"id":"profile","steps":[],"final":"ok"}' \
    '{profile_id: "claude-coding-local", model: "claude-sonnet-5", repository_id: "sample-app", message: $m}')")
SID=$(echo "$created" | jq -r .session_id)
curl -sS "$API/v1/sessions/$SID" -H "Authorization: Bearer $KEY" | jq .runtime
```

```text
{
  "kind": "claude_agent_sdk",
  "version": "0.3.270",
  "profile_id": "claude-coding-local",
  "model": "claude-sonnet-5",
  "permission_mode": "default"
}
```

A profile that is not in the catalog, a profile that cannot run with that repository, and a model the profile does not allow all return 422.

When you create an agent release, choose with `runtime_profile_id`. The card's `model` must be one of the models that profile can run, and all of the card's tools must be in the profile ([Create](/agents/create#create-a-release)).

## Change the profile of a running session

Change it with `POST /v1/sessions/{id}/profile`. The running turn finishes with the profile it started with, and input from then on runs with the new profile. The conversation and working tree continue from the last checkpoint. Changing to the same profile changes nothing and only leaves a receipt.

```bash
until [ "$(curl -sS "$API/v1/sessions/$SID/turns/1" -H "Authorization: Bearer $KEY" | jq -r .status)" = completed ]; do
  sleep 2
done
REV=$(curl -sS "$API/v1/sessions/$SID" -H "Authorization: Bearer $KEY" | jq .revision)
curl -sS "$API/v1/sessions/$SID/profile" \
  -H "Authorization: Bearer $KEY" \
  -H 'Content-Type: application/json' \
  -H "Idempotency-Key: $(uuidgen)" \
  -d "$(jq -nc --argjson r "$REV" '{expected_revision: $r, profile_id: "claude-coding-local"}')" | jq -c .
```

```text
{"receipt_id":"…","receipt_status":"succeeded"}
```

If the new profile differs in runtime kind, version, or billing mode, or does not pair with that repository, the response is 422 `UNSUPPORTED_CAPABILITY`. For a session created from an agent release, the release decides the profile, so the response is 409 `RELEASE_PROFILE_MISMATCH`. The scope is `sessions:control`.

## Make a workspace profile

Workspace owners and admins can make a profile that only this workspace uses, based on an operator profile. In the console, open **Workspace › Run profiles** and press **Make a profile**.

- It can only reduce. Models and tools are picked from the base profile's, and the permission mode is the base profile's own or one that has a person check more. The runtime, provider, credential and repository pairing stay the base profile's.
- A saved version never changes. Each save after **Edit** makes a new version id `ws_<workspace slug>_<name>_v<n>`, which the screen shows before you save. A release on an earlier version changes only when you make a new release on the new version. The list shows one row per name with its latest version; press **Earlier versions (N)** to unfold the rest.
- Pressing a row opens its detail (`/profiles/<id>`): models, tools, permission mode, base profile, the versions under the same name, and the agents whose active release uses that version. Only people who can manage agents see the agent list. An owner or admin opens the editor with the current values from **Edit** on the detail, and starts a new workspace profile from an operator profile's detail with **Make a profile from this**.
- The list (`GET /v1/profiles`) holds the operator's profiles (`source: "operator"`) and this workspace's versions (`source: "workspace"`) together. The console cannot change an operator profile. The operator catalog cannot use ids starting with `ws_`, so the two never collide.
- When the operator changes the base profile, the version becomes **Base profile changed**; when the operator removes it, **Base profile removed**. No new release or session can use that version. Use **Make again** on a version whose base profile changed to make a new one.
- A version that is **Turned off** cannot be picked by new releases or sessions. Releases and sessions that already use it keep running. Turning a version off cannot be undone.
- A release's profile list shows operator profiles and workspace profiles in separate groups, and a version that takes no new release cannot be picked.
- Members only read the list. Only owners and admins signed in to the console can make, edit and turn off versions (`POST /v1/workspace-profiles`, `POST /v1/workspace-profiles/{profile_id}/retire`); an API key gets 403.

Auto rules and the script ceiling have a place on the screen but cannot be changed yet.
