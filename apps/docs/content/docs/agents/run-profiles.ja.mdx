---
title: "実行プロファイルを選ぶ"
description: セッションがどのモデル・ツール・権限モードで動くかを決める実行プロファイル
---

実行プロファイル (profile) は、セッションの動作方式を決める。runtime とそのバージョン、モデル、ツール一覧、権限モード、モデル provider、リポジトリを使うかどうかである。運用者が環境のカタログ (`config/profiles.yaml`) にプロファイルを登録し、ユーザーは id を指定して選ぶ。リポジトリごとに動作できるプロファイルの一覧もカタログ (`config/repositories.yaml`) にある。

## 一覧を見る

```bash
curl -sS "$API/v1/profiles" -H "Authorization: Bearer $KEY" | jq '.items[]'
```

```text
{
  "id": "claude-coding-local",
  "model": "claude-sonnet-5",
  "tools": [
    "Read",
    "Edit",
    "Write",
    "Glob",
    "Grep",
    "Bash",
    "AskUserQuestion"
  ],
  "runtime_kind": "claude_agent_sdk",
  "runtime_version": "0.3.270",
  "billing": "metered",
  "repository_mode": "required"
}
```

| フィールド | 意味 |
| --- | --- |
| `model` | デフォルトのモデル |
| `tools` | セッションで使えるツール。これ以外のツールは実行されない ([権限](/agents/permissions)) |
| `billing` | `metered` ならコストをセッションの上限に計上する。`none` なら計上しない |
| `repository_mode` | `required` (リポジトリ必須)、`optional`、`none` (リポジトリなし) |

provider のアドレスと認証情報は一覧に表示されない。その値は worker にも渡されない。

## セッションで選ぶ

セッションを作成するとき、`profile_id` で選ぶ。プロファイルが複数のモデルを許可している場合は `model` でその中の 1 つを選び、省略するとデフォルトのモデルで動く。

```bash
created=$(curl -sS "$API/v1/sessions" \
  -H "Authorization: Bearer $KEY" \
  -H 'Content-Type: application/json' \
  -H "Idempotency-Key: $(uuidgen)" \
  -d "$(jq -nc --arg m 'GATE-SPEC {"id":"profile","steps":[],"final":"ok"}' \
    '{profile_id: "claude-coding-local", model: "claude-sonnet-5", repository_id: "sample-app", message: $m}')")
SID=$(echo "$created" | jq -r .session_id)
curl -sS "$API/v1/sessions/$SID" -H "Authorization: Bearer $KEY" | jq .runtime
```

```text
{
  "kind": "claude_agent_sdk",
  "version": "0.3.270",
  "profile_id": "claude-coding-local",
  "model": "claude-sonnet-5",
  "permission_mode": "default"
}
```

カタログにないプロファイル、そのリポジトリで動作できないプロファイル、プロファイルが許可していないモデルは 422 になる。

エージェントのリリースを作成するときは、`runtime_profile_id` で選ぶ。カードの `model` がそのプロファイルで実行できるモデルのひとつで、カードのツールがすべてプロファイルにある必要がある ([作成](/agents/create#リリースの作成))。

## 進行中のセッションのプロファイルを変更する

`POST /v1/sessions/{id}/profile` で変更する。実行中のターンは開始時のプロファイルで終わり、その次の入力から新しいプロファイルで動く。会話と作業ツリーは最後の checkpoint から引き継がれる。同じプロファイルに変更しても何も変わらず、receipt だけが残る。

```bash
until [ "$(curl -sS "$API/v1/sessions/$SID/turns/1" -H "Authorization: Bearer $KEY" | jq -r .status)" = completed ]; do
  sleep 2
done
REV=$(curl -sS "$API/v1/sessions/$SID" -H "Authorization: Bearer $KEY" | jq .revision)
curl -sS "$API/v1/sessions/$SID/profile" \
  -H "Authorization: Bearer $KEY" \
  -H 'Content-Type: application/json' \
  -H "Idempotency-Key: $(uuidgen)" \
  -d "$(jq -nc --argjson r "$REV" '{expected_revision: $r, profile_id: "claude-coding-local"}')" | jq -c .
```

```text
{"receipt_id":"…","receipt_status":"succeeded"}
```

新しいプロファイルの runtime の種類・バージョンや課金方式が異なる場合、またはそのリポジトリと組み合わせられない場合は 422 `UNSUPPORTED_CAPABILITY` になる。エージェントのリリースで作成したセッションは、リリースがプロファイルを決めるため 409 `RELEASE_PROFILE_MISMATCH` になる。scope は `sessions:control` である。

## ワークスペースで絞る

ワークスペースのオーナーと管理者は、運営者のプロファイルを 1 つ選び、このワークスペースだけで使う絞った版を作れます。コンソールの **ワークスペース › 実行プロファイル** で **絞ったプロファイルを作成** を押します。

- 絞ることだけができます。モデルとツールは基準のプロファイルにあるものから選び、権限モードは基準と同じか、人がより多く確認するモードだけを選べます。runtime、provider、認証情報、リポジトリとの組み合わせは基準のプロファイルのものをそのまま使います。
- 保存した版は変わりません。保存するたびに新しい id `ws_<ワークスペースの slug>_<名前>_v<n>` ができ、画面は保存前にその id を表示します。版を使う release は、新しい版で release を作り直すまで変わりません。
- 一覧(`GET /v1/profiles`)には運営者のプロファイル(`source: "operator"`)とこのワークスペースの版(`source: "workspace"`)が一緒に出ます。コンソールは運営者のプロファイルを変更できません。運営者のカタログは `ws_` で始まる id を使えないため、両者は重なりません。
- 運営者が基準のプロファイルを変更すると版は **基準が変更**、削除すると **基準なし** になります。その版では新しい release とセッションを作れません。基準が変わった版は **作り直す** で新しい版を作ります。
- **引退** した版は新しい release とセッションが選べません。すでにその版を使う release とセッションは動き続けます。引退は元に戻せません。
- release のプロファイル一覧は運営者のプロファイルとワークスペースの版を分けて表示し、新しい release を受けない版は選べません。
- メンバーは一覧を見るだけです。作成と引退はコンソールにログインしたオーナー・管理者だけができ(`POST /v1/workspace-profiles`、`POST /v1/workspace-profiles/{profile_id}/retire`)、API key では 403 です。

auto ルールとスクリプト上限は画面に場所だけがあり、まだ変更できません。
