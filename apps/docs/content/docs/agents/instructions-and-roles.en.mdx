A card is the definition that says who an agent is and what it should do. Editing a card creates a new version, and earlier versions never change.

## Card fields

| Field | Required | Content |
| --- | --- | --- |
| `role` | Yes | One-line role. Up to 200 characters |
| `instructions` | Yes | Instructions. Up to 20,000 characters |
| `model` | Yes | Model name. Must be one of the models the run profile can run when you create a release |
| `capabilities.tools` | Yes | List of tool names to use. They must be tools the run profile has. `null` means all of the profile's tools when the release is created |
| `capabilities.mcp` | Yes | Only `null` is accepted for now |
| `capabilities.forbidden` | | Tool names to forbid. The web console puts `[]` on a new card, and only shows and clears an existing value |
| `capabilities.tool_policy` | | `allow`, `ask`, or `deny` per tool |
| `capabilities.credential_refs` | | Names of the credentials to use (not the values). [Permissions](/agents/permissions) |
| `language` | | `ko` (default) or `en` |
| `rules` | | List of `{id, text, source}`. `source` is `user` or `correction` |

## Choosing tools in the web console

In card editing (the "What it does" step of a new agent, and card editing on the agent's page), "Tools it may use" is a checklist of one profile's tools.

- "Profile to choose tools from": pick one of the profiles that run the card's model. The new-agent flow lists first the profiles it can release without a repository, and picks the chosen one first in the release step. This value is not saved on the card.
- With "Every tool the profile allows at release" on, `tools` is `null`. Turn it off and the checked tools are `tools`. Unchecking a tool is what forbids it.
- When saving, the `tool_policy.per_tool` entries of unchecked built-in tools are removed, because a release refuses a policy for a built-in tool it does not run. MCP tool policies stay.
- A name in `tools` that the profile does not have shows checked as "Not in the profile" and can only be turned off.
- Below the list is the number of profiles that allow every tool chosen. At 0, the card cannot be saved.
- An existing card's `forbidden` shows as a list, and "Clear blocked tools" empties it. Until then, those tools stay off in the checklist and cannot be changed.

## What the model reads today

<Callout type="warn">
A card's `role`, `instructions`, and `rules` are stored in the version and the release and pinned to the session, but they are not passed to the model yet.
</Callout>

The worker currently adds two instructions to the model.

- `CLAUDE.md` at the repository root. When the run profile has `project_settings.claude_md: true`, the committed content is read. The local profile `claude-coding-local` has it on.
- For a session without a repository, a single line telling the agent to put files meant for people in `out/`.

So to tell an agent how to work, write it in the repository's `CLAUDE.md` for now.

## Editing and versions

Editing a card makes `PATCH /v1/agents/{id}` add a new version. To change only the name, send only `name`. Sending a card identical to an existing version adds nothing. This continues with `AID` and `WEB` from [Create](/agents/create).

```bash
curl -sS -X PATCH "$API/v1/agents/$AID" "${WEB[@]}" -d '{
  "card": {
    "role": "저장소를 읽고 질문에 답한다",
    "instructions": "Answer briefly. Cite file paths. Say when you are unsure.",
    "model": "claude-sonnet-5",
    "language": "en",
    "capabilities": { "tools": ["Read", "Grep", "Glob"], "mcp": null },
    "rules": [{ "id": "no-guess", "text": "Never invent a file path.", "source": "user" }]
  }
}' | jq -c '.versions[] | {version_no, language: .card.language}'
```

```text
{"version_no":1,"language":"ko"}
{"version_no":2,"language":"en"}
```

A new version does not change the active release. To use it, create a release from that version and activate it ([Create](/agents/create#create-a-release)). In the web console, "Save" on the agent detail does the same thing and shows the difference between the two versions.
