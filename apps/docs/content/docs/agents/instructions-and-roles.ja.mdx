エージェントには、人が見る値と実行に使われる値が別々にある。

| 値 | 置き場所 | 変更すると | モデルが読むか |
| --- | --- | --- | --- |
| 名前 (`name`)・説明 (`description`) | エージェントの行 | すぐに変わる。バージョンもリリースも作られない | [プラットフォーム段落](#現在モデルが読むもの)を有効にしたインストールでのみ読む |
| エージェント指示文 (`agent_instructions`) とその他のカードのフィールド | カード | 新しいバージョンが作られる。そのバージョンのリリースで開始したセッションから使われる | 指示文は読む |

名前と説明は、一覧や詳細画面でエージェントを見分けるための値である。プラットフォーム段落を有効にしたインストールでは、モデルもこの 2 つの値を書かれたとおりに読むので、事実だけを書く。エージェントの仕事の進め方はエージェント指示文に書く。

## エージェント指示文

エージェント指示文は、そのエージェントのセッションごとにシステムプロンプトに追加される文章である。`CLAUDE.md` や `AGENTS.md` に書いていた仕事の進め方、答え方、守るべきルールをここに書く。20,000 文字まで。

Web コンソールでは、エージェント詳細の「詳細設定」タブで「詳細設定を編集」を押し、「実行設定」の「エージェント指示文」に書いて保存する。新しいエージェントの流れにはこの欄はない。エージェントを作成したあと、詳細設定で書く。

- 保存すると新しいバージョンが作られる。有効なリリースはそのままである。
- そのバージョンでリリースを作成すると、そのリリースで開始したセッションのシステムプロンプトに追加される。プラットフォームの指示のあと、リポジトリの `CLAUDE.md` の前である。有効化すると、Slack のようにリリースを自分で選ばない経路が新しいセッションに使うリリースがそれに変わる。
- セッションは開始時のリリースに固定される。セッションの実行環境が再び立ち上がるとき (最後のターンのあと入力がないまま 30 分経って実行環境が停止した後のメッセージ、または一時停止後の再開) も、そのリリースの指示文を再び追加するため、有効なリリースを変えても進行中のセッションの指示文は変わらない。
- 空にしたり空白だけを残したりすると、カードから外れ、プロンプトには何も追加されない。書いた文章は前後の空白も含めてそのまま保存する。

### 指示文の書き方

エージェントの役割は作成者が決める。プラットフォームは役割や性格を決める文を入れず、プラットフォームだけが知る事実と安全ルールだけを追加する。その内容は[現在モデルが読むもの](#現在モデルが読むもの)にある。

- 経験年数や誇張した修飾を書かない。「経験 30 年の最高のシニア開発者」のような言葉は、何を担当するのかを伝えない。
- 担当範囲は一行で書く。
- 許可する行動は具体的な動詞で書き、理由を添える。理由があれば、書いていない状況でも同じ基準で判断できる。

```text
決済障害の分析を担当する。
ログを読んで原因を要約する。
変更は担当チームがレビューするので、コードは修正しない。
```

### 以前の指示

以前のカードには「ロール」(`role`) と「指示事項」(`instructions`) の欄があった。この 2 つの値はバージョンに保存されたが、モデルに渡されたことはない。

- 新しく作るカードはこの 2 つの値を送らない。すでに保存されたバージョンの値はそのまま残る。
- ロールは、この機能が入ったときにエージェントの説明へ一度だけ移した。説明のないエージェントは、画面でカードのロールを代わりに表示する。
- 指示事項は自動では移さない。移すと、人が確認していない文章が既存のエージェントの動作を変えてしまうためである。詳細設定に「以前の指示（適用されたことはありません）」として表示され、編集画面の「エージェント指示文に取り込む」を押すと、その文章が指示文の欄に入る。保存し、そのバージョンのリリースでセッションを開始して初めて実行に使われる。

## カードのフィールド

| フィールド | 必須 | 内容 |
| --- | --- | --- |
| `agent_instructions` | | エージェント指示文。20,000 文字まで。空なら入れない |
| `model` | はい | モデル名。リリースを作成するとき、プロファイルで実行できるモデルのひとつでなければならない |
| `capabilities.tools` | はい | 使うツール名の一覧。プロファイルにあるツールでなければならない。`null` ならリリース作成時のプロファイルのツールすべて |
| `capabilities.mcp` | はい | 現在は `null` のみ受け付ける |
| `capabilities.forbidden` | | 禁止するツール名。Web コンソールは新しいカードに `[]` を入れ、既存の値は表示して消すことだけができる |
| `capabilities.tool_policy` | | ツールごとの `allow`・`ask`・`deny` |
| `capabilities.credential_refs` | | 使う認証情報の名前 (値ではない)。[権限](/agents/permissions) |
| `language` | | `ko` (デフォルト) または `en` |
| `rules` | | `{id, text, source}` の一覧。`source` は `user` または `correction` |
| `role`・`instructions` | | 以前のカードの値。モデルには渡されない。新しいカードには送らない |

名前 (1〜120 文字) と説明 (0〜2,000 文字) はカードではなくエージェントのフィールドである。`POST /v1/agents` と `PATCH /v1/agents/{id}` に `name`・`description` として送る。

## Web コンソールでツールを選ぶ

カードの編集 (新しいエージェントの「役割」ステップ、エージェント詳細の詳細設定の編集) の「使用できるツール」は、プロファイル 1 つのツールのチェックリストである。

- 「ツールを表示するプロファイル」: カードのモデルを実行するプロファイルからひとつ選ぶ。新しいエージェントの流れでは、リポジトリなしでリリースできるプロファイルを先に並べ、選んだプロファイルをリリースのステップで先に選んでおく。この値はカードに保存しない。
- 「リリース時にプロファイルがブロックしていないすべてのツール」がオンなら `tools: null` である。オフにすると、チェックしたツールが `tools` になる。チェックを外すことが禁止である。
- 保存するとき、チェックを外した組み込みツールの `tool_policy.per_tool` の項目を消す。リリースは実行しない組み込みツールのポリシーを拒否するためである。MCP ツールのポリシーは残る。
- `tools` にプロファイルにない名前があれば「プロファイルにないツール」としてチェックされたまま表示され、オフにすることだけができる。
- 一覧の下に、選んだツールをすべて許可するプロファイルの数が出る。0 なら保存できない。
- 既存のカードに `forbidden` があれば一覧で表示され、「禁止ツールを消す」で空にできる。空にするまでは、チェックリストのそのツールはオフのまま変更できない。

## 現在モデルが読むもの

worker がモデルのシステムプロンプトに追加する指示は、この順序である。

1. プラットフォーム段落。インストール設定 `SESSION_PROMPT_REVISION` が `1` のときに追加される。既定値の `0` では追加されない。
2. リポジトリのないセッションでは、人に渡すファイルを `out/` に置くよう指示する 1 行。
3. セッションのリリースのエージェント指示文。
4. リポジトリルートの `CLAUDE.md`。プロファイルが `project_settings.claude_md: true` のとき、コミットされた内容を読む。ローカルプロファイル `claude-coding-local` では有効になっている。

プラットフォーム段落には、役割や性格を決める文はない。プラットフォームだけが知る事実と安全ルールだけを含む。

- エージェントの名前と説明。書かれたとおりに伝える。
- セッションを開始した場所と回答の言語（カードの `language`）、セッションのリポジトリの GitHub 名。
- GitHub の作業に使うツールとその使い方。
- 安全ルール。push できるブランチ、トークンを求めないこと、エージェント指示文では使えるツールを変更できないこと。

これらの値はセッションを作成するときに保存する。名前や説明を変更しても、進行中のセッションの段落は変わらない。

<Callout type="warn">
カードの `role`・`instructions`・`rules` はモデルに渡されない。プラットフォーム段落のないインストールでは、名前・説明とカードの `language` も渡されない。そのようなインストールで回答の言語を決めるには、エージェント指示文に書く。
</Callout>

## 修正とバージョン

カードを送ると、`PATCH /v1/agents/{id}` が新しいバージョンを追加する。名前や説明だけを変えるときは `name`・`description` だけを送る。このときバージョンは作られない。すでにあるバージョンと同じカードを送った場合は何も追加されない。[作成](/agents/create)の `AID` と `WEB` を引き続き使う。

```bash
curl -sS -X PATCH "$API/v1/agents/$AID" "${WEB[@]}" -d '{
  "description": "リポジトリを読んで質問に答える",
  "card": {
    "agent_instructions": "Answer briefly. Cite file paths. Say when you are unsure.",
    "model": "claude-sonnet-5",
    "language": "en",
    "capabilities": { "tools": ["Read", "Grep", "Glob"], "mcp": null },
    "rules": [{ "id": "no-guess", "text": "Never invent a file path.", "source": "user" }]
  }
}' | jq -c '.versions[] | {version_no, language: .card.language}'
```

```text
{"version_no":1,"language":"ko"}
{"version_no":2,"language":"en"}
```

新しいバージョンは有効なリリースを変更しない。使うには、そのバージョンでリリースを作成して有効化する ([作成](/agents/create#リリースの作成))。Web コンソールでは、詳細設定の「保存」が同じ処理を行い、2 つのバージョンの差分を表示する。
