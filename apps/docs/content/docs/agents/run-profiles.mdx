---
title: "실행 프로필 고르기"
description: 세션이 어떤 모델·도구·권한 모드로 도는지 정하는 실행 프로필
---

실행 프로필(profile)은 세션이 도는 방식을 정한다: runtime과 그 버전, 모델, 도구 목록, 권한 모드, 모델 provider, 저장소를 쓰는지. 프로필은 운영자가 설치의 카탈로그(`config/profiles.yaml`)에 등록하고, 사용자는 id로 고른다. 저장소마다 돌 수 있는 프로필 목록도 카탈로그(`config/repositories.yaml`)에 있다.

## 목록 보기

```bash
curl -sS "$API/v1/profiles" -H "Authorization: Bearer $KEY" | jq '.items[]'
```

```text
{
  "id": "claude-coding-local",
  "model": "claude-sonnet-5",
  "tools": [
    "Read",
    "Edit",
    "Write",
    "Glob",
    "Grep",
    "Bash",
    "AskUserQuestion"
  ],
  "runtime_kind": "claude_agent_sdk",
  "runtime_version": "0.3.270",
  "billing": "metered",
  "repository_mode": "required"
}
```

| 필드 | 뜻 |
| --- | --- |
| `model` | 기본 모델 |
| `tools` | 세션에서 쓸 수 있는 도구. 밖의 도구는 실행되지 않는다([권한](/agents/permissions)) |
| `billing` | `metered`면 비용을 세션 상한에 센다. `none`이면 비용을 세지 않는다 |
| `repository_mode` | `required`(저장소 필수), `optional`, `none`(저장소 없음) |

provider 주소와 자격 증명은 목록에 나오지 않는다. 그 값은 worker에도 가지 않는다.

## 세션에서 고르기

세션을 만들 때 `profile_id`로 고른다. 프로필이 모델을 여럿 허용하면 `model`로 그중 하나를 고르고, 빼면 기본 모델로 돈다.

```bash
created=$(curl -sS "$API/v1/sessions" \
  -H "Authorization: Bearer $KEY" \
  -H 'Content-Type: application/json' \
  -H "Idempotency-Key: $(uuidgen)" \
  -d "$(jq -nc --arg m 'GATE-SPEC {"id":"profile","steps":[],"final":"ok"}' \
    '{profile_id: "claude-coding-local", model: "claude-sonnet-5", repository_id: "sample-app", message: $m}')")
SID=$(echo "$created" | jq -r .session_id)
curl -sS "$API/v1/sessions/$SID" -H "Authorization: Bearer $KEY" | jq .runtime
```

```text
{
  "kind": "claude_agent_sdk",
  "version": "0.3.270",
  "profile_id": "claude-coding-local",
  "model": "claude-sonnet-5",
  "permission_mode": "default"
}
```

카탈로그에 없는 프로필, 그 저장소에서 돌 수 없는 프로필, 프로필이 허용하지 않는 모델은 422다.

에이전트 release를 만들 때는 `runtime_profile_id`로 고른다. 카드의 `model`이 그 프로필이 실행할 수 있는 모델 중 하나이고, 카드의 도구가 모두 프로필에 있어야 한다([만들기](/agents/create#release-만들기)).

## 진행 중인 세션의 프로필 바꾸기

`POST /v1/sessions/{id}/profile`로 바꾼다. 돌고 있는 turn은 시작한 프로필로 끝나고, 그다음 입력부터 새 프로필로 돈다. 대화와 작업 트리는 마지막 checkpoint에서 이어진다. 같은 프로필로 바꾸면 아무것도 바뀌지 않고 receipt만 남는다.

```bash
until [ "$(curl -sS "$API/v1/sessions/$SID/turns/1" -H "Authorization: Bearer $KEY" | jq -r .status)" = completed ]; do
  sleep 2
done
REV=$(curl -sS "$API/v1/sessions/$SID" -H "Authorization: Bearer $KEY" | jq .revision)
curl -sS "$API/v1/sessions/$SID/profile" \
  -H "Authorization: Bearer $KEY" \
  -H 'Content-Type: application/json' \
  -H "Idempotency-Key: $(uuidgen)" \
  -d "$(jq -nc --argjson r "$REV" '{expected_revision: $r, profile_id: "claude-coding-local"}')" | jq -c .
```

```text
{"receipt_id":"…","receipt_status":"succeeded"}
```

새 프로필이 runtime 종류·버전이나 과금 방식이 다르거나 그 저장소와 짝이 아니면 422 `UNSUPPORTED_CAPABILITY`다. 에이전트 release로 만든 세션은 release가 프로필을 정하므로 409 `RELEASE_PROFILE_MISMATCH`다. scope는 `sessions:control`이다.

## 워크스페이스에서 좁히기

워크스페이스 owner와 admin은 운영자 프로필 하나를 골라 이 워크스페이스에서만 쓰는 좁힌 판을 만든다. 콘솔의 **워크스페이스 › 실행 프로필**에서 **좁힌 프로필 만들기**를 누른다.

- 좁히기만 된다. 모델과 도구는 기준 프로필에 있는 것 중에서 고르고, 권한 모드는 기준과 같거나 사람이 더 많이 확인하는 모드만 고른다. runtime, provider, 자격 증명, 저장소 짝은 기준 프로필의 것을 그대로 쓴다.
- 저장한 판은 바뀌지 않는다. 저장할 때마다 새 id `ws_<워크스페이스 slug>_<이름>_v<n>`이 생기고, 화면은 저장 전에 그 id를 보여 준다. 판을 쓰는 release는 새 판으로 release를 다시 만들어야 바뀐다.
- 목록(`GET /v1/profiles`)에는 운영자 프로필(`source: "operator"`)과 이 워크스페이스의 판(`source: "workspace"`)이 함께 나온다. 콘솔은 운영자 프로필을 고치지 못한다. 운영자 카탈로그는 `ws_`로 시작하는 id를 쓸 수 없어서 둘이 겹치지 않는다.
- 운영자가 기준 프로필을 바꾸면 판은 **기준 바뀜**, 지우면 **기준 없음**이 된다. 그 판으로는 새 release와 세션을 만들 수 없다. 기준이 바뀐 판은 **다시 만들기**로 새 판을 만든다.
- **은퇴**한 판은 새 release와 세션이 고를 수 없다. 이미 그 판을 쓰는 release와 세션은 계속 돈다. 은퇴는 되돌릴 수 없다.
- release의 프로필 목록은 운영자 프로필과 워크스페이스 판을 나눠 보여 주고, 새 release를 받지 않는 판은 고를 수 없다.
- 구성원은 목록만 본다. 만들기와 은퇴는 콘솔에 로그인한 owner·admin만 할 수 있고(`POST /v1/workspace-profiles`, `POST /v1/workspace-profiles/{profile_id}/retire`), API key로는 403이다.

auto 규칙과 스크립트 상한은 화면에 자리만 있고 아직 고칠 수 없다.
