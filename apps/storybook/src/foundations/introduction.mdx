# @werft-ai/ui · @werft-ai/react

agent-platform 콘솔이 쓰는 UI 키트다. 사이드바는 패키지의 층과 같은 순서로 놓았다.

- **Foundations** · `packages/ui/src/foundations` — 토큰(`tokens.css`), Tailwind 연결(`theme.css`), BEM 기본(`styles.css`).
- **Primitives** · `packages/ui/src/primitives` — 아무것도 모른다. shadcn/ui 항목과 `Skeleton`.
- **Patterns** · `packages/ui/src/patterns` — primitives를 조합한다.
- **Domain** · `packages/react/src/components`(`@werft-ai/react/components`) — `@werft-ai/contracts` 타입을 받는다. Session·Status·Receipt·Feedback.
- **Blocks** · `packages/react/src/blocks`(`@werft-ai/react/blocks`) — provider와 query로 데이터를 붙인 화면 단위.
- **Screens** · 스토리 전용 — 위 조각으로 만든 화면 한 칸의 상태. 시안도 여기에 둔다(아래).

## 시안은 Screens 스토리로만

- 시안은 `apps/storybook/src/screens/*`의 스토리다. 실제 `@werft-ai/ui`·`@werft-ai/react` 부품을 조립하고 데모 데이터를 넣는다.
- 따로 그린 HTML 캔버스 시안은 만들지 않는다.
- 시안에서 고른 모양은 먼저 부품에 넣고(ui-kit), 화면은 그 부품으로 조립한다(web-ui).
- 시안에 필요한 모양이 부품에 없으면 부품 추가 요청이다. 시안 안에서 따로 그리지 않는다.

컴포넌트마다 해당하는 상태를 같은 이름의 스토리로 둔다: `Default`·`Disabled`·`Invalid`·`Loading`·`Empty`·`Error`.
`States`는 그 상태들을 한 열에 모은 것이고, `(dark)`·`(390px)`·`(English)`·`(日本語)`가 붙은 스토리는 테마·폭·언어를 고정한 사본이다.
툴바의 Theme(light/dark)와 Language(한국어/日本語/English)는 고정하지 않은 스토리에 적용된다.
모든 스토리는 CI에서 실제 Chrome으로 한 번씩 그려지고, axe 위반이 있으면 실패한다.

화면을 짤 때의 규칙은 [화면 구성 원칙](https://github.com/JeongJaeSoon/agent-platform/blob/main/packages/ui/README.md#화면-구성-원칙)을 따른다.
토큰 값은 Foundations/Tokens에, 두 테마는 Foundations/Light and dark에 나란히 있다.

## 설치

두 패키지는 아직 이 저장소의 워크스페이스 private 패키지다(`"private": true`). 저장소 안에서는 `package.json`에 이렇게 적는다.

```json
"dependencies": {
  "@werft-ai/ui": "workspace:*",
  "@werft-ai/react": "workspace:*"
}
```

저장소 밖의 앱에 `@werft-ai/ui`를 tarball로 설치하는 법은 문서의 [저장소 밖 앱에 설치](https://jeongjaesoon.github.io/agent-platform/ui/package/)에 있다. 레지스트리에는 아직 게시하지 않았다.

## 쓰는 쪽이 갖출 의존성

지금 `package.json` 기준이다.

`@werft-ai/ui`는 `react`·`react-dom`(`^19.3.0`)을 `peerDependencies`로 받는다. 앱의 React를 그대로 쓰며, 사본이 둘이 되면 hook이 깨진다.
Radix·`class-variance-authority`·`clsx`·`tailwind-merge`·`lucide-react`는 `dependencies`로 함께 설치된다. 쓰는 쪽이 따로 설치할 것은 다음과 같다.

- `react`·`react-dom` 19 — peer.
- `tailwindcss` 4 — 아래 CSS 경로 1에서만.
- 글꼴 — 배포 tarball에는 글꼴이 없다. 쓰는 쪽 앱이 Geist·Pretendard를 로드한다(아래 "폰트").

`@werft-ai/react`는 런타임 의존성을 하나도 선언하지 않는다(모두 `devDependencies`). 쓰는 쪽이 설치할 것은
`react`, `@tanstack/react-query` 5, `react-hook-form`, `@hookform/resolvers`, `zod`, `@use-funnel/core`, `lucide-react`,
그리고 워크스페이스의 `@werft-ai/ui`·`@werft-ai/client`·`@werft-ai/core`·`@werft-ai/contracts`다.

## CSS

### 경로 1: Tailwind 4 앱

앱의 CSS에서 이 순서로 import하고, Tailwind가 키트 소스를 스캔하게 한다(`apps/web/src/styles.css`가 예다).

```css
@import "tailwindcss";
@import "@werft-ai/ui/styles.css";
@import "@werft-ai/ui/theme.css";

@source "<키트까지의 경로>/packages/ui/src";
@source "<키트까지의 경로>/packages/react/src";
```

`theme.css`가 토큰을 Tailwind 유틸리티(`bg-primary`·`rounded-control`·`text-control` 등)에 잇는다.
키트 규칙은 `ap` cascade layer에 있어 Tailwind 유틸리티 뒤, 앱의 layer 밖 규칙 앞에 온다.

### 경로 2: 미리 빌드한 CSS

배포 tarball(`bun run --cwd packages/ui build:package`가 만드는 `dist`)의 `styles.css`는 Tailwind CLI로 미리 빌드한 CSS다.
토큰·`ap-*` 규칙·키트가 쓰는 유틸리티가 들어 있어, Tailwind 없는 앱도 `import "@werft-ai/ui/styles.css"` 한 줄로 그려진다.
preflight는 넣지 않고, 키트 요소와 그 안쪽에만 거는 preflight 대체 규칙을 넣는다. 다만 함께 빌드되는 `theme.css`가 모든 요소의 `border-color`를 `--ap-color-border`로 정한다.
저장소 워크스페이스의 `@werft-ai/ui/styles.css`는 빌드 전 소스라 이 경로가 아니라 경로 1로 쓴다.

preflight가 없는 앱에서 키트가 어떻게 보이는지는 Foundations/No preflight에서 본다. preflight를 shadow root로 막고 경로 1의 나머지만 적용한 화면이다.

## 폰트

배포 tarball에는 글꼴이 없다. 빌드가 `styles.css`의 `fonts.css` import를 빼므로, 쓰는 쪽 앱이 Geist·Geist Mono·Pretendard를 로드하지 않으면 `--ap-font-sans`·`--ap-font-mono`는 시스템 글꼴로 떨어진다.
저장소 워크스페이스에서는 소스 `styles.css`가 `fonts.css`를 import한다. Geist·Geist Mono는 `src/foundations/fonts/`에 있고, 한글은 `devDependencies`의 `pretendard` dynamic subset을 쓴다. CDN에서 받는 글꼴은 없다.

## 테마

라이트가 기본이다. 다크는 시스템 설정(`prefers-color-scheme`)을 따르고, `<html data-theme="dark">` 또는 `data-theme="light"`로 직접 고정할 수 있다.
