# 에이전트의 Slack 연결

에이전트 상세의 **Slack** 탭에서 앱 상태를 확인한다. 새 에이전트는 이름·하는 일·릴리스·켜기를 마친 뒤 **채널 연결** 단계에서 같은 화면을 사용한다. Slack 연결은 나중에 해도 된다.

앱을 설치하면 Slack 탭은 한 페이지가 된다. 맨 위 상태 줄에 연결 상태·봇 ID·홈 채널·DM 받기가 있고, 아래로 **채널**, **기본**, **고급**, **위험 구역**이 이어진다. 왼쪽 구역 목록에서 고르면 그 구역으로 이동한다. 좁은 화면에서는 목록이 본문 위의 버튼 하나로 접힌다. 버튼에는 지금 보는 구역 이름이 보인다. 펼쳐서 구역을 고르면 목록이 다시 접힌다.

1. 에이전트를 켠 뒤 **Slack 앱 만들고 설치**를 누른다. 워크스페이스 관리자가 앱 생성 설정(App Configuration Token)을 먼저 해 두어야 한다. 설정이 없거나 Slack이 더 이상 받지 않으면 버튼이 꺼지고 아래에 이유가 나온다. 소유자·관리자에게는 **워크스페이스 Slack 설정으로** 링크가, 그 밖의 에이전트 관리자에게는 소유자나 관리자에게 요청하라는 안내가 붙는다.
2. Slack 동의 화면에서 앱을 설치한다. 콜백이 설치를 마치면 Slack 탭으로 돌아오고 화면 아래에 설치 결과 알림이 뜬다. 거절하거나 링크가 만료되면 실패 알림과 함께 Slack 탭에서 새 설치를 시작한다. 이미 사용한 링크는 다시 보내지 않는다. 권한이나 이벤트 설정이 바뀌면 **고급**의 앱 카드에서 **다시 설치**를 누른다. 같은 카드의 앱 ID 행에서 **복사**로 앱 ID를 복사하고, **Slack에서 열기**로 Slack의 앱 설정 페이지를 새 탭에서 연다.
3. 설치한 뒤 홈 채널이 없으면 Slack 탭은 **홈 채널 지정** 단계만 보인다(**고급**·**위험 구역**은 그대로 있다). **홈 채널 고르기**에서 채널을 고르면 그 채널이 사용 켜짐과 홈으로 저장되고 나머지 구역이 나타난다. 비공개 채널은 목록에 `/invite` 안내가 붙는다.
4. **채널** 구역의 **채널 추가**에서 이름 앞부분으로 검색하고 **연결**을 누른다. 연결 결과는 화면 아래 알림으로 뜬다. 연결한 채널마다 **이 채널에서 사용**과 **멘션할 때만 반응** 스위치가 있다. 사용을 끄면 그 채널에서 반응하지 않고, 멘션할 때만 반응을 끄면 멘션 없이 채널에 쓴 글에도 반응한다. 새로 추가하거나 에이전트를 초대한 채널은 사용이 켜진 채로 연결된다. **기본**의 **새 채널의 기본 반응** 스위치는 새 채널이 멘션할 때만 반응할지 정하고, 바꾸는 즉시 서버에 저장된다. 이미 연결된 채널은 바뀌지 않는다. 처음 값은 멘션할 때만이다. **DM 받기** 스위치는 DM binding을 별도로 저장한다.
5. 꺼 둔 채널을 다시 사용으로 켜면 멘션할 때만 반응하는 상태로 돌아온다. 저장 실패는 화면에 표시되고 기존 설정을 유지한다. 홈 채널은 **홈 지정**으로 바꾼다.

공개 채널은 반응이 켜진 채로 연결하거나 나중에 반응을 켜면 서버가 봇을 참여시킨다. 반응이 꺼진 채널에는 참여하지 않는다. 비공개 채널은 봇이 스스로 들어갈 수 없으니 `/invite`로 초대해야 한다. 봇이 아직 없는 비공개 채널에는 **/invite 필요** 태그와 복사 버튼이 붙는다. 버튼을 누르면 `/invite @<에이전트 slug>`를 클립보드에 복사한다. 브라우저가 클립보드를 막으면 명령을 선택한 칸을 보여 주니 직접 복사한다. 검색은 봇이 볼 수 있는 공개 채널과 이미 참여한 비공개 채널을 보여 준다. **더 보기**로 다음 페이지를 읽는다. Slack 요청 제한으로 결과가 오래됐거나 목록 상한에 걸리면 안내를 표시한다.

**위험 구역**의 **Slack 연결 해제** 행에서 **연결 해제**를 누르면 에이전트의 Slack 신원과 채널 연결을 회수한다. Slack 앱은 남아 있어 다시 설치할 수 있다. **Slack 앱 삭제** 행의 **앱 삭제**는 Slack 앱과 저장된 자격을 삭제한다. 되돌릴 수 없고, 다시 연결하면 새 앱이 생긴다. 두 행동 모두 영향을 설명하는 확인창을 거친다.

구역 목록의 링크를 Enter로 고르면 그 구역으로 포커스가 옮겨 간다. Tab으로 스위치에 이동해 Space로 반응을 바꾼다. 결과와 오류는 보조 기술에도 알린다.

설치 뒤 이벤트 등록이 끝나지 않으면 콜백에 확인 필요 안내가 나온다. **고급**의 **이벤트 Request URL** 행은 Slack이 주소를 확인했는지(확인됨·확인 대기·등록 실패·아직 보내지 않음)를 보여 주고, **다시 확인**으로 주소를 Slack에 다시 보낸다. 주소를 보냈는데 Slack이 아직 확인하지 않았으면 상태 줄 위에 안내와 Slack 앱 설정의 Event Subscriptions 화면 링크가 나온다. 주소를 보내기 전에는 이 안내를 띄우지 않는다. 실 Slack의 멘션 응답 및 회수 뒤 이벤트 처리는 별도 사람 검증이 필요하다.

**에이전트** 목록의 **전체** 탭에서는 Slack 탭이 사람에게 할 일을 요구하는 에이전트에만 카드와 표 행에 **Slack 조치 필요: <이유>** 링크가 붙는다. 링크는 그 에이전트의 Slack 탭을 연다. 이유는 하나만 보이고, Slack 탭이 먼저 보이는 일이다. 설치 전이면 앱 설치 대기, 봇 연결이 해제되거나 앱이 제거됐으면 다시 설치 필요다. 설치돼 있으면 이 순서로 먼저 걸리는 것이다: 이벤트 주소 확인 대기(주소를 보낸 뒤), 홈 채널 지정 필요, 이벤트 주소 등록 실패. 앱이 없거나 설정이 끝난 에이전트에는 링크가 없다. API는 `GET /v1/agents?include=summary`의 `summary.slack_action`이다. **관리하는 에이전트** 탭의 목록에는 요약이 없어 링크도 없다.

소유자·관리자의 **홈**에는 이런 에이전트가 있을 때만 **지금 할 일**이 **시작하기** 위에 나온다. 행마다 `Slack <이유>`, 에이전트 이름, 그 때문에 생기는 일이 보이고, **고치기**를 누르면 그 에이전트의 Slack 탭이 열린다. 세 건까지 보이고, 더 있으면 **전체 보기 N건**이 에이전트 목록으로 간다. 홈은 목록 첫 100개만 읽으니, 에이전트가 그보다 많으면 건수 뒤에 "이상"이 붙는다. 그 100개 밖의 에이전트에만 조치가 필요하면 지금 할 일은 나오지 않는다.
