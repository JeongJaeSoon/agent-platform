# 에이전트의 Slack 연결

에이전트 상세의 **Slack** 탭에서 앱 상태를 확인한다. 새 에이전트는 이름·하는 일·배포 판·켜기를 마친 뒤 **채널 연결** 단계에서 같은 화면을 사용한다. Slack 연결은 나중에 해도 된다.

앱을 설치하면 Slack 탭은 한 페이지가 된다. 맨 위 상태 줄에 연결 상태·봇 ID·홈 채널·DM 받기가 있고, 아래로 **채널**, **기본**, **고급**, **위험 구역**이 이어진다. 왼쪽 구역 목록에서 고르면 그 구역으로 이동한다. 좁은 화면에서는 목록이 본문 위의 버튼 하나로 접힌다. 버튼에는 지금 보는 구역 이름이 보인다. 펼쳐서 구역을 고르면 목록이 다시 접힌다.

1. 에이전트를 켠 뒤 **Slack 앱 만들고 설치**를 누른다. 워크스페이스 관리자가 앱 생성 설정을 먼저 해 두어야 한다.
2. Slack 동의 화면에서 앱을 설치한다. 콜백이 설치를 마치면 Slack 탭으로 돌아오고 화면 아래에 설치 결과 알림이 뜬다. 거절하거나 링크가 만료되면 실패 알림과 함께 Slack 탭에서 새 설치를 시작한다. 이미 사용한 링크는 다시 보내지 않는다. 권한이나 이벤트 설정이 바뀌면 **고급**의 앱 카드에서 **다시 설치**를 누른다. 같은 카드의 앱 ID 행에서 **복사**로 앱 ID를 복사하고, **Slack에서 열기**로 Slack의 앱 설정 페이지를 새 탭에서 연다.
3. **채널** 구역의 **채널 추가**에서 이름 앞부분으로 검색하고 **연결**을 누른다. 연결 결과는 화면 아래 알림으로 뜬다. **기본**의 **새 채널의 기본 반응** 스위치는 바꾸는 즉시 서버에 저장되고, 그 뒤 새로 연결하는 채널에 적용된다. 이미 연결된 채널은 바뀌지 않는다. 처음 값은 꺼짐이다. **DM 받기** 스위치는 DM binding을 별도로 저장한다.
4. 연결된 채널의 스위치를 켜면 멘션에 반응하고, 끄면 해당 채널에서 반응하지 않는다. 저장 실패는 화면에 표시되고 기존 설정을 유지한다. 홈 채널은 **홈 지정**으로 바꾼다.

공개 채널은 연결하면 서버가 봇을 참여시킨다. 비공개 채널은 봇이 스스로 들어갈 수 없으니 `/invite`로 초대해야 한다. 봇이 아직 없는 비공개 채널에는 **/invite 필요** 태그와 복사 버튼이 붙는다. 버튼을 누르면 `/invite @<에이전트 slug>`를 클립보드에 복사한다. 브라우저가 클립보드를 막으면 명령을 선택한 칸을 보여 주니 직접 복사한다. 검색은 봇이 볼 수 있는 공개 채널과 이미 참여한 비공개 채널을 보여 준다. **더 보기**로 다음 페이지를 읽는다. Slack 요청 제한으로 결과가 오래됐거나 목록 상한에 걸리면 안내를 표시한다.

**위험 구역**의 **Slack 연결 해제** 행에서 **연결 해제**를 누르면 에이전트의 Slack 신원과 채널 연결을 회수한다. Slack 앱은 남아 있어 다시 설치할 수 있다. **Slack 앱 삭제** 행의 **앱 삭제**는 Slack 앱과 저장된 자격을 삭제한다. 되돌릴 수 없고, 다시 연결하면 새 앱이 생긴다. 두 행동 모두 영향을 설명하는 확인창을 거친다.

구역 목록의 링크를 Enter로 고르면 그 구역으로 포커스가 옮겨 간다. Tab으로 스위치에 이동해 Space로 반응을 바꾼다. 결과와 오류는 보조 기술에도 알린다.

설치 뒤 이벤트 등록이 끝나지 않으면 콜백에 확인 필요 안내가 나온다. 현재 조회 API에는 이벤트 등록 상태·확인 시각·공개 이벤트 주소가 없으므로 이후 방문에서 이를 추측해서 표시하지 않는다. 실 Slack의 멘션 응답 및 회수 뒤 이벤트 처리는 별도 사람 검증이 필요하다.
