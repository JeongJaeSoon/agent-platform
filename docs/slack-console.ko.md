# 에이전트의 Slack 연결

에이전트 상세의 **Slack** 탭에서 앱 상태를 확인한다. 새 에이전트는 이름·하는 일·배포 판·켜기를 마친 뒤 **채널 연결** 단계에서 같은 화면을 사용한다. Slack 연결은 나중에 해도 된다.

1. 에이전트를 켠 뒤 **Slack 앱 만들고 설치**를 누른다. 워크스페이스 관리자가 앱 생성 설정을 먼저 해 두어야 한다.
2. Slack 동의 화면에서 앱을 설치한다. 콜백이 설치를 마치면 Slack 탭으로 돌아온다. 거절하거나 링크가 만료되면 Slack 탭에서 새 설치를 시작한다. 이미 사용한 링크는 다시 보내지 않는다.
3. **채널**에서 이름 앞부분으로 검색하고 **연결**을 누른다. 새 채널에 적용할 반응을 스위치로 고른다. 이 선택은 현재 화면에서 추가하는 채널에만 적용한다.
4. 연결된 채널의 스위치를 켜면 멘션에 반응하고, 끄면 해당 채널에서 반응하지 않는다. 저장 실패는 화면에 표시되고 기존 설정을 유지한다. 홈 채널은 **홈 지정**으로 바꾼다.

공개 채널은 서버가 자동 참여하고, 비공개 채널은 `/invite`로 봇을 초대해야 한다. 검색은 봇이 볼 수 있는 공개 채널과 이미 참여한 비공개 채널을 보여 준다. **더 보기**로 다음 페이지를 읽는다. Slack 요청 제한으로 결과가 오래됐거나 목록 상한에 걸리면 안내를 표시한다.

**연결 해제**는 에이전트의 Slack 신원과 채널 연결을 회수한다. **앱 삭제**는 Slack 앱과 저장된 자격을 삭제한다. 두 행동 모두 영향을 설명하는 확인창을 거친다.

키보드로 탭에 포커스한 뒤 화살표로 탭을 바꾸고, Tab으로 스위치에 이동해 Space로 반응을 바꾼다. 결과와 오류는 보조 기술에도 알린다.

설치 뒤 이벤트 등록이 끝나지 않으면 콜백에 확인 필요 안내가 나온다. 현재 조회 API에는 이벤트 등록 상태·확인 시각·공개 이벤트 주소가 없으므로 이후 방문에서 이를 추측해서 표시하지 않는다. 실 Slack의 멘션 응답 및 회수 뒤 이벤트 처리는 별도 사람 검증이 필요하다.
